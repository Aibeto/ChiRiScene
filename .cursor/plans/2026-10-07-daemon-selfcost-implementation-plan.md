# daemon 自耗归因与调度优化实施计划（合并版）

> 状态（2026-10-07 更新）：阶段 A 已完成；阶段 B/C(部分)/D1 代码已实施并暂存，**全部「未验证」**（验证状态见 `.trae/docs/2026-10-07-selfcost-phase-bcf-results.md` 与台账 07）；C3/C5/D4/E/F 未实施。编译测试与设备验收仍未取得授权。
> 本文件合并 CodeBuddy 原计划与 Cursor 修订版，是本专项唯一有效计划。原版已废弃，修订版不再保留有效副本。
> 执行时使用 writing-plans / executing-plans 技能逐阶段核对；每阶段需取得对应授权，不自动创建 worktree、安装依赖或提交。

**目标：** 查清 daemon 自耗，实施不降低采样质量的确定优化，减少诊断工作对调度事件的直接阻塞，并将经证据确认的非 FAS 热点转成优化任务；不承诺未经测量的 CPU 或功耗降幅。

**架构：** A 校正离线工具，B 原路径测量并固定基线，C 分批实施确定优化，D 将可以保持时点保真的诊断工作移出调度线程，E 按归因证据优化非 FAS 热点，F 统一验收。全部内容在本文件内维护；阶段闸门用于隔离风险与授权，不要求另建实施计划。

**技术：** Python 标准库、现有 devimp CSV/日志、Rust `Instant`、Android/Linux 线程 CPU 时钟，不增加第三方依赖。

## 2. 证据与约束

1. P1≈26 / P3≈29 / P2≈86 ms/s 是跨场景推导的量级提示，不是测量基线或验收目标。亮屏总量减息屏估计的帧成本，不作严格分解。
2. 30～40ms 是进程 CPU 配对估计，不是调度线程墙钟阻塞。`/proc/self/stat` 覆盖整个进程，不完整覆盖 eBPF 系统事件路径；墙钟耗时不能从进程 CPU 中扣除。
3. 落行次数不等于执行次数，tick 行有签名去重。配对负差不能单独证明选择偏差或系统忙导致跳帧。
4. main 日志首尾覆盖不能证明全程诊断开启，覆盖之外也不证明关闭。轮转、归档、缺日志与关闭分开处理。
5. 缺少 status 秒数不等于丢行率；挂起、停机、缺文件与未知缺口不能混为一谈。未知缺口不补零、不外推。
6. 不为本专项调大 `aff_secs`、主动关闭 devimp、暂停 clamp、摘遥测或缓存当前值使采样变粗。已有非默认样本可分层分析，禁止新增采集开关对照实验。
7. 所有测量调用进入汇总，≥50ms 只用于节流告警。只采慢帧不能建立成本基线。
8. ≤0.05% 合计及1～3ms微优化量级不是直接测量上界，不作为收益承诺；policy缓存、电池TTL和token优化不混入本专项基线采集。
9. 不可变上下文仍不能保证异步 stat 读取时点不滞后；诊断线程化必须验证采集时延，不预先宣称不降质。

### B1 测量定义

- [ ] 墙钟端点为before_build、after_build、after_write、after_summary，build与write分别记账，总同步成本覆盖前两段，summary另记。
- [ ] build/write同时用当前线程 `CLOCK_THREAD_CPUTIME_ID` 两端差分记CPU。读取失败记unavailable及错误次数，不用0或进程时间兜底。

- [ ] CPU读取无效仍计wall/count，CPU分母取cpu_valid_count，分母0输出unavailable。每次调用入账，慢阈值只限制告警；不每帧额外读/proc，不持全局锁累计。

### B2 输出与生命周期

- [ ] 累计器由同步采集线程独占，仅diag_active且实际采样时计时，关闭时不继续探测，不改门控。
- [ ] 每60s或诊断会话结束输出独立 `selfcost_*.log`，沿用logger的devimp目录、轮转、归档预算路径，不产生无界文件，不改现有格式。
- [ ] 固定字段为schema、session、window_start/end、block、count、cpu_valid_count、wall_ns_sum/max、cpu_ns_sum、wall_buckets、slow_count、clock_errors、write_errors；记录测量schema和配置身份。
- [ ] CPU区间不重叠，外层总区间不再作为可加项；墙钟均值sum/count，CPU均值cpu_sum/cpu_valid_count，会话结束输出不足60s尾窗。
- [ ] 测量失败不阻断原采集，摘要写失败明确告警并标测量不完整，不丢原aff帧以保摘要。

### B3 归因与验收

- [ ] 先只测@S build/write，不同时改token、缓存或线程归属，以免基线变化。
- [ ] 同会话/同窗口对齐进程CPU与被测块CPU；仅CPU读数完整且边界可对齐时给部分账，墙钟不从进程CPU中相减。
- [ ] 区分其它线程、测量本身、摘要写入和未测成本，负残差保留调查，不截0，不归入eBPF系统事件成本。

- [ ] 固定迁移前清单、版本配置、分层CPU和墙钟分布后，再讨论第二批候选块；先核入口可达性、线程归属、嵌套关系，每批只增加少数点。

## 6. 阶段 C：确定的实现优化

入口：B的原始基线已固定；若缺设备测量，可在单独授权下实现候选，但必须标记收益未验证。按C1～C4分批，每批独立对拍和记录，不把几项收益混成一个数字。

### C1 token惰性构造与借用快路径

- [ ] `logger::aff_token` 返回 `Cow<'_, str>`，无空白/控制字符时借用；需要替换时逐字符应用原映射，保留Unicode、空串、真值`-`及NaN占位处理原语义。
- [ ] `build_aff_snapshot` 只在刷新帧、comm变化、首见及每PID本帧首条线程名称兜底需要时构造token；保持候选、stat读取、util基线、排序与刷新计数不变。
- [ ] 将每PID首条兜底从“所有线程都有token”的隐式依赖变成显式记录；不缓存原始comm跨采样点，不省略原来必需的读取。
- [ ] 测试覆盖空白/控制字符/Unicode/空串/`-`、刷新/差分/首见/首条兜底；用相同采样输入对比优化前后aff完整字节流。借用返回值不得跨其源字符串生命周期保存。

### C2 CLG/tuned tick去重前格式化

- [ ] `main_tick` 接收原始数值和reason字段，CLG/tuned调用点同步适配；policy_id和cluster仍分别参与去重key，不回到同簇多policy冲突。
- [ ] 使用标准库 `fmt::Write` 在栈缓冲中生成与旧代码完全相同的签名；比较格式化字节，不用f32位比较。缓冲溢出时回退旧完整堆格式化，不截断、不漏字段。
- [ ] 去重确定需要落行后才格式化raw_util/prev_perf等展示字段；保留格式精度、时间门槛、状态更新时间及reason语义。
- [ ] 测试舍入边界、负零、非有限值、reason变化、时间门槛、policy2/5同簇独立状态和缓冲溢出；对同一tick输入序列比较签名、落行选择和输出字节。

### C3 CPU频率快照policy发现缓存

- [ ] 缓存仅作用于 `cpu_freq_snapshot` 的发现结果与基础路径，实际cur/min/max等数值每次照旧读取，不改变 `get_cpu_policies` 的初始化/接管用途。
- [ ] 首次空或失败不永久缓存；非空缓存60s重扫，失败保留旧列表，实际拓扑增删后重建。扫描和写缓存不跨节点读取持锁。
- [ ] 测试首次失败恢复、空列表恢复、TTL边界、重扫失败、增删、ID排序和节点读取失败；静态拓扑输出逐字节一致。
- [ ] 运行期新增policy最多延迟60s发现是语义边界，不称绝对输出不变。仅在目标平台拓扑稳定依据已记录且该边界获批准时实施；否则本项保持受阻，不以延迟发现换取采样质量。

### C4 PowerBase电池状态TTL（条件项）

- [ ] 先取得允许压频判定感知延迟的明确批准；未批准则本项不实施，其余阶段继续。
- [ ] 缓存仅放PowerBase，TTL=2s，仅缓存成功有效状态，过期重读；失败不刷新旧缓存并按原“非放电”失败语义处理，下次调用重试。
- [ ] 进入/退出PowerBase清缓存，未知值告警仍由实际读取触发。status.csv charge和PowerAVG取样门保留新鲜读取，不能全局缓存函数。
- [ ] 测试放电/充电切换、TTL边界、读取失败/未知值、退出重入及告警去重；文档说明延迟在持续调用条件下是TTL加下一次调用等待，不无条件承诺墙钟2s。

### C5 快照内分配优化（测量后条件项）

- [ ] B确认分配/解析为值得处理的成本后，复用读缓冲及临时容器，不减少线程枚举、stat或亲和查询；按原解析输入处理短读和线程退出。
- [ ] 每帧清理容器逻辑长度，容量超过历史正常规模后可收缩；避免大型前台退出后永久保留峰值内存。不把tid/comm身份跨帧盲目缓存。
- [ ] 对固定样本逐字节对拍，并记录分配次数及RSS变化；只调整syscall排布不能当作减少syscall收益。

交付：实际完成/受阻项清单、字节与决策语义对拍结果、分批成本记录。收益无法测得时写未验证，不写预计节省已兑现。

## 7. 阶段 D：诊断去阻塞与线程化

本阶段在本计划内设计、实施和验收，不另建plan。入口为B原始基线固定、C已实施批次记录完整，且用户批准迁移实施。优先低风险移走渲染/写入，再决定是否搬走实际采样。

### D1 明确职责与任务

- [ ] 诊断worker为单线程，任务包含session_generation、sequence、采样起止时刻、前台身份、配置身份、full标记及不可变采样结果；不访问可变AffinityManager或控制器。
- [ ] 首选路径在调度线程原时点完成必要stat/亲和读取和差分判定，发布owned采样结果，worker做行渲染与aff批次写入。分拆 `build_aff_snapshot` 的采样/差分与渲染边界，不改变采集字段。
- [ ] 帧基线和刷新序号由采样侧唯一持有；只在D4整体采样迁移获批准后才交给worker，不能两侧同时推进 `AFF_SNAP_TICK` 或线程基线。
- [ ] 一批包含完整帧头与所有行，logger保持帧批次原子写入，不与@A行交错。保留原timestamp语义；新增时序字段放独立selfcost记录，不悄悄替换采样时间为落盘时间。

### D2 有界队列、顺序和失败

- [ ] 用有界FIFO，初始容量2个完整帧任务，报告字节容量与峰值内存，不用覆盖式latest槽。单帧允许原有全部候选，不为容量截断行数。
- [ ] 队列满时按原序阻塞交付完整任务，明确这是保真优先的回压，不宣称永不阻塞；不在调度线程持控制锁等待。测量排队及回压时长，若普遍回压则停止扩大异步范围。
- [ ] worker失败或通道关闭时先确认已交付序号/未提交任务及最后写出帧；不能把同一帧同步重写成重复帧。正常路径单写者，失败切回同步前要完成单写者交接。
- [ ] 无法确认部分写入时记录诊断故障、回到现有logger自愈语义并明确缺失风险，不称零丢帧；禁止因诊断错误更改调度策略或默默继续不完整输出。

### D3 生命周期与共享资源

- [ ] 前台切换不把历史任务改标为新包，按sequence完成旧帧再处理新帧；诊断代际更改只隔离基线，不盲目丢弃旧队列。
- [ ] 正常诊断关闭/停机先排空已采任务并输出尾窗，之后释放worker和日志句柄；热重载每任务绑定其时点配置，不在消费时套用新配置。
- [ ] 不在worker增加会写调度节点的逻辑，不新增强制CPU绑定或抢占优先级。检查logger锁范围，避免把IO锁等待重新传回主调度路径。
- [ ] 退出与故障的等待超时不能同时承诺无丢帧；异常退出保留原保证等级，新增风险写入验收，不自动通过。

### D4 整体采样迁移（条件项，不保证一定实施）

- [ ] 仅D1～D3通过后评估：在原采样到期点发布一致的前台/受管表/managed PID/配置/序号上下文，并由worker实际读取。
- [ ] 用B测量加发布到开始、采集起止、队列深度/回压计数确认时点偏移；需要控制事件等待指标时只加汇总计时，不逐帧刷日志或改变事件合并/投递语义。
- [ ] 原时点与worker实际读取期间有身份改变或短促线程结束时，判断原可观测信息是否丢失；时间戳不能弥补未读取的历史状态，不以“字段一样”宣称保真。
- [ ] 无法证明不降质时保留D1同步采样、异步渲染/写入方案，D4标为受阻。不可强行整体迁移或退而降采样。

### D5 验收

- [ ] 确定性测试涵盖FIFO满队列、顺序、双policy/前台切换、诊断开关、配置代际、partial write、worker失败、退出排空；校验无重复序号、无跨身份拼接及full存活集合语义。
- [ ] 固定输入对拍原与新aff字节和合并状态；自然真机观察采样延迟、缺帧、full刷新、调度事件等待、同步块CPU/墙钟和内存。未取得设备授权就只给实现/静态状态。
- [ ] 不能只用daemon总CPU判断成功；异步可能增加CPU但降低主线程同步等待，分别报告。缺少延迟或保真证据时不标迁移验收通过。

## 8. 阶段 E：归因驱动的非 FAS 调度热点优化

入口：A/B已给出候选或确认成本。C/D不是发现新热点的必要条件；但不能和它们同批修改同一基线。此阶段是本计划的实施内容，不以“另写计划”结束。

### E1 分块归因

- [ ] 按证据优先级选择CLG负载处理、tuned tick、thermal周期块、affinity apply/rebalance、monitor采样、日志落盘之一，每批只测少数块。
- [ ] 先核调用入口、频度、线程、嵌套和diag门控；累计实际执行数、线程CPU、墙钟，不从tick行数反推执行次数。按场景/身份记录，不跨版本混算。
- [ ] 将已知成本、未测成本、测量误差、覆盖不足分别列出；能复现总量不意味着分块正确。无证据热点保持未归因，不编造实现改动。

### E2 候选到实现的规则

- [ ] CLG/tuned：优先处理同tick重复解析/转换、容器构造及可证明冗余的计算；保留死区、dwell、触摸floor、温控输入及强制再断言。不再次添加已否决的降后禁升周期。
- [ ] affinity：只在确认重复工作后复用同轮输入/临时容器，保留现有扫描节奏、身份核验、热窗、释放和重试；不恢复已否决的“cgroup内容未变就不查cmdline”。
- [ ] thermal/monitor：复用已采数据只限相同采样时点和相同语义，不缓存温度或负载使控制输入陈旧；不以事件化替代既有轮询或削减探针。
- [ ] 节点写入：核对已有值去重是否实际生效，仅修确认的重复写；失败重试、防篡改兜底、接管/释放写入不得作为冗余删除。
- [ ] 为确认热点在本节追加一个编号任务，必须填写具体文件/函数、前置条件、旧/新数据流、保持的决策不变量、失败/释放路径、测试输入及收益测量窗。填完并获批准才改代码，不创建第二份plan。
- [ ] 每项单独实施并回放相同输入，比较频率目标、动作顺序、模式迁移、释放与重试；只声称实测且可归因的收益，无收益或增加复杂度则停止该项并记录结论。

本节具体新热点实现是证据驱动的条件任务，不是漏项：未知热点不能预先命名代码修改，但测量、决策、填入本计划、实施和验收流程都必须交付。

## 9. 结果分流

1. 有显式诊断关闭证据及可比样本，仍观察到常驻自耗：定位常驻路径，不能据此直接承诺收益或改参数。
2. 可比样本显示主要成本在诊断开启期间：优先查诊断实现，保持采样面和时间精度；无关闭证据不得作此结论。
3. 校正方法或直接测量后，粗略剩余量明显改变：先更新方法与量级提示，不在旧数上排序优化项。
4. 样本不足、状态未知或窗口无法对齐：交付确认部分与不可识别项，不强行补齐归因；新增实现/设备工作仍须授权。

所有结果均保持不降采样质量约束；导向C/D/E对应任务，不在调查报告处终止整个优化专项，也不自动授权实施。
