## 归档/导出压缩改内置库（不依赖设备 gzip/lz4 二进制）

用户要求：gz 与 lz4 两种格式都改用模块自带的相关库，设备环境缺这两种二进制也能正常打包。
上一条「pack.sh archive 内 lz4 -f、设备无 lz4 回落 .tar」的方案随即作废（该设备实测就是走的回落分支）。

改动：
- **依赖**：`Cargo.toml` 新增 `flate2`（`rust_backend`，miniz_oxide 纯 Rust，免链系统 zlib）与
  `lz4_flex`（纯 Rust lz4 帧格式，产物与标准 lz4 工具互通）。均为流式 `io::copy`，不整读
  100MB+ 归档进内存。
- **启动归档（daemon 进程内）**：`pack.sh archive` 还原为纯 tar；`logger.rs` 新增
  `compress_lz4`/`compress_gzip`，`pack_or_keep` 在 tar 打包成功后就地压成 `.tar.lz4` 并删中间
  tar；仅 lz4 落盘 I/O 失败才回落保留 `.tar`（不再存在「设备无 lz4」这一常见分支）。
- **导出 gzip（shell 侧）**：pack.sh export 的 gzip 主选改为模块二进制工具模式
  `core/bin/chiri gzip <file>`（main.rs `[toolbox]` 分发：arg1 ∈ {gzip,lz4} 时进 CLI 压缩后
  exit，语义对齐 `gzip -f`；必须在 daemonize 之前分发，看门狗传的模块目录绝对路径不会撞名），
  系统 gzip → busybox gzip 兜底；WebUI export 流程与轮询协议（fail/progress/total/.mode 文件）
  零改动。
- 文档同步：`docs/agents/02-convention.md` 归档条/devimp 条/导出条、`.cursor/memory/MEMORY.md`
  归档格式 bullet。

自证：mtime 前移后 `cargo check -p chiri --target aarch64-linux-android`，`Checking chiri v2.0.2`
+ `Finished` + exit 0、0 条 rustc warning。第一版把 lz4_flex `finish` 的自家 `frame::Error` 链进
`io::Result` 被 E0308 抓出（自证纪律生效的一次实锤），已改为 copy/finish 分开判。scratch
`devimpbin/tmp_lz4_check.*` 已删。本轮终端调用 5 次（超限原因：两次引号转义失败 + 一次
PowerShell stderr 流吞 Checking 行 + 一次真错复跑 + 一次修后复跑）。

**待验**：上真机跑一轮重启归档，确认 logd/ 产出 `.tar.lz4`（dvlz4.py 按内容嗅探，无需改动）；
WebUI 导出确认 `.tar.gz` 由内置 gzip 产出（`chiri gzip` 退出码 0）。
