## 关键发现（数字均可复算）
1. **sm8550 侧亲和写大面积失败**：`place` EINVAL 62,531（80%），ok 里又有 54% 被裁剪 →
   真正生效的 EEM 迁移仅 **≈9.5%**；`pin fg_pin` 失败 **90.5%**（63,856）。sm8750 几乎零失败。
2. **失败呈爆发**：单批次一半失败集中在 14 秒（0.7% 的有动作秒），单秒最高 431 条，
   形态 = **同一 pid 的 417 个线程全部钉向同一颗核、整批 ok=0**。
3. **放大机制两条**：`core_pinned` 只在写成功时计数 → 失败不占位 → 整批挑同一颗核（选核塌缩）；
   失败不记 `last_mask_write` → `mask_write_skip` 不命中 → 每轮（≈150ms）硬撞，实测单 pid 单核 1 分钟 390~417 次。
4. **状态分叉**：`Engine::tick` 无条件推进状态机与 window，而 `st.eem_window` 只在写成功且未裁剪时更新 →
   失败后「引擎记账 / 内核掩码 / eem_window」三方不一致，「先扩后缩」每拍落地的前提被打破。
5. **预算才是当前限流器**：有 place 动作的秒里 **78% 打满 `EEM_MAX_MOVES_PER_ROUND`=4**。
6. **迁移总量大头不在我们**：sn8550 实测 wakeups/migrations = akmode 21,929/10,395/s、boost 12,999/7,272/s、
   default 10,724/5,649/s（÷2 后），而 ChiRi 自身 @A 生效迁移仅 ≈0.2/s —— 与 A02-14 报告 §8.3 的结论一致。
7. **能量画像**（sm8550 3.7h 批次）：整机均值 2.24 W，**无一次热压制**（cap=100 全程）；
   按包 QQ 3.05 W（26% 能量）、ChatGPT 1.98 W、Claude 1.87 W、miui.home 1.27 W、微信 3.10 W。
