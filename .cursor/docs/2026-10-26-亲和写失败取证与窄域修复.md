## 1. 硬结论（可复核数字）

| 指标 | sm8550/PHB110（14 批） | sm8750/2410DPN6CC（22 批） |
| --- | --- | --- |
| `place` 写失败 e22 | **62,531（80%）** | 116 |
| `place` 写「成功」但被裁剪 | **8,617（54% of ok）** | 26 |
| 真正生效的 EEM 迁移 | **≈7,400 / 78,500 ≈ 9.5%** | ≈16,670 / 16,700 |
| `pin fg_pin` 失败率 | **90.5%（63,856 次）** | 0 |
| 卡死线程（连续同标的重复 ≥5 次） | 35 个，最长 16 次 | 0 |

- **失败不是均匀分布**：单个批次里**一半失败集中在 14 秒内**（占 2,110 个有动作秒的 0.7%），单秒最高 **431 条**。
- **爆发形态**：那 431 条全部是**同一个 pid（QQ）的 417 个线程、全部钉向同一颗核（5 或 6）**、全部 EINVAL（整批 ok=0）。`place` 侧同理，最大单秒 417 条。
- **方向分布**（sm8550 全量 126,555 次 EINVAL）：`pin→big` 62,796、`place→little` **61,852**、`pin→prime` 1,228、`place→big` 679。
- sm8750 侧同一份代码几乎零失败 —— **平台差异，不是逻辑差异**。

## 2. 放大机制（为什么「一个小拒绝」变成 12 万次白写）

1. **失败不占位 → 选核塌缩**：`pick_core_pref` 用 `core_pinned` 计数分散钉定，而 `add_pinned` 只在**写成功**后执行。写失败时计数不涨，整批线程反复挑中同一颗「最闲」核 → 全部撞同一颗核全灭。
2. **失败不节流 → 每轮硬撞**：`pin_core` 失败直接 `return`，`record_mask_write` 不记；`mask_write_skip` 的 `recent` 分支因此永不命中，下一轮（≈150ms）继续重试。实测同一 pid 对同一颗核**一分钟 390~417 次**。
3. **两拍协议不设回滚 → 三方状态分叉**：`placement::Engine::tick` 无条件把状态机推到下一拍、把 `e.window` 改成目标；而 `st.eem_window` 只在「写成功且未裁剪」时才更新。写失败后「引擎记账 / 内核掩码 / eem_window」各说各话，「先扩后缩」每拍落地的前提被打破，下一轮按假窗口重新规划 → 每轮再失败一次（`MIN_DWELL`=2s 一次）。

## 3. 机理判别（内核为什么拒）

三种候选，现有证据如下：

| 候选 | 支持证据 | 反对证据 |
| --- | --- | --- |
| **cgroup cpuset 收窄**（该 pid 的允许核不含目标核） | 同一秒内**同一 pid 的数百个线程**齐灭、被判相同的簇；`place→little` 与 `pin→big` 两个方向都大面积失败，符合「不同 cgroup 各锁一个核域」 | 同一 (pid, 核) 在别的时段能成功，cpuset 一般较稳定 |
| **目标核此刻不可用**（WALT halt / offline） | 时间成簇、同一核成批失败 | `clamp_change` 显示 `corectl=policy0:3/3/0;policy3:4/4/1;policy7:0/1/1` —— big 簇 min=max=4（全留），只有 prime 可暂停；且 @S `t` 行的 `core=` 在 0-7 全核都有采样 |
| **32 位线程钉无 AArch32 簇** | 会给出 EINVAL | `mask_write_allowed` 已前置拦截，且拦截路径打 `e0` 而非 `e22` |

**结论目前只能到「进程级核域受限」这一层**（三次独立判据都指向它）。决定性判别留给下一轮日志：
- 新增 `place ... eff=<lo>-<hi>`（回读掩码）与 `read_fail` 标记，可直接看出「意图 vs 实际」被摘掉哪些核；
- 若下轮 `pin fg_pin e22` 大幅下降且 `place` 失败集中在特定 pid，即可判定为 cpuset 侧；若仍与核号相关，则是核可用性侧。

## 4. 已落地改动（本轮）

### 4.1 `src/chiri/placement.rs`（纯逻辑，可离线回归）

- `Entry` 新增 **`applied` / `applied_cluster`**（最近一次**确认生效**的区间与簇 = 回滚锚点）与 **`fail_streak`**。
- 新增 **`Engine::note_applied(tid, cluster, mask, now)`**：以**回读掩码**为锚点（不是写入意图），并清零失败计数。
- 新增 **`Engine::abort(tid, now) -> Option<u8>`**：失败即退回锚点、状态机回稳态、失败计数 +1。
- `tick` 冷却改为「`MIN_DWELL`/反跳回冷却」与「失败退避」取大者：**`FAIL_BACKOFF_BASE`=4s × 2^(n-1)，封顶 `FAIL_BACKOFF_MAX`=30s**。
- 新增 `#[cfg(test)] Engine::entry()` 只读查询（仅测试构建存在，不进生产热路径）。

### 4.2 `src/chiri/affinity.rs`

- `ThreadState` 新增 **`pin_fail_streak`**；`record_mask_write` 成功即清零。
- 新增 **`pin_fail_wait()`**：单核钉定连续失败 n 次后等 `REPIN_DEBOUNCE(8s) × 2^(n-1)`，封顶 **`PIN_FAIL_BACKOFF_MAX`=60s**，退避期内连 `@A` 帧都不产生。
- 新增**进程级窄核域备忘** `narrow_pid: HashMap<i32, (CoreGroup, Instant)>` + `narrow_skip()` / `note_narrow()`：**只在 EINVAL 记账**（ESRCH/ENOENT 不记），有效期 **`NARROW_PID_TTL`=15s**，前台 pid 或 boost 状态一变立刻清表。
- `pin_core`：写前查窄域与退避闸；失败分支补记账（计数 + `last_mask_write`）与窄域记账。
- `eem_place_round`：写前查窄域（命中则**回滚引擎并跳过**）；`mv`（升组）失败也回滚；写成功 → `note_applied`（并顺手修掉「过渡步拿意图当窗口」的隐患）；写失败/读回空 → `note_narrow` + `abort`；`@A` 的 `value` 追加 **`eff=`** 回读掩码。

### 4.3 判读口径变化（下行给分析侧）

`@A` 帧数量**大幅减少属预期**：失败不再每轮重打、同 pid 同簇整批跳过。判「有没有在动作」要看 **`place ... settled=false` 的成功条数**与 `restore/pin ok`，不要看总帧数。

## 6. 预期收益（口径见上）

按「单 pid × 单簇 × 15s」去重：sm8550 的 **126,555 次 EINVAL → 约 4,190 次尝试，降幅 ≈30×**。叠加逐线程指数退避与成功即清零，稳态应按「每个 (pid, 簇) 每分钟 ≤4 次」收敛。同时消掉的是：等量 `@A` 白行（devimp 预算压力）、每轮 syscall 延迟、以及失败后按假窗口重规划带来的持续震荡。
