## 二、归因

1. **2.15 core-hour 的构成**：亮屏 6460 核秒（83%）+ 息屏 1206 核秒。亮屏均 77ms/s 主要由 @S 周期构建（1s 节奏，含 read_dir/stat/格式化）+ @A 动作产生；息屏 36ms/s 是 5s 节奏下的残余 tick + 巡检底噪。build p50 58.6ms 本身贴着 50ms 阈值 → 一半的告警是"常态略超"而非异常尖峰；p99 尖峰是系统争用（与线程规模无关，见 1.2）。
2. **重启 8 次全部是 devimp 日志 128MB 归档预算**，与 daemon 逻辑/内存泄漏无关；4~9h 间隔与亮屏时长（写日志速率）正相关。重启代价已实测很小（1.3）。
3. **e22 702 条（聚合计数）≠ 退避失效**：按设计退避生效（74% tid 恢复、真持续仅 2%）；大头（99%）在 dst=group 兜底写入路径，且富集于 CLG 载入场景 → 最可能机制是**组掩码目标与该线程当时生效 cpuset 不相交（scenemode/CLG 收窄 cpuset 后，兜底组掩码仍写全 little/big 集合）→ 内核 EINVAL**；walt_halt 来源（已知坑 11，.cursor/commands/devimp-log-analysis.md:329-332）只解释单核路径的 59 条。来源是"CLG 切换瞬态 + 兜底路径不感知 cpuset"，不是来源转移。
4. uclamp/bg_apply e2(ENOENT) 27/批是节点缺失常态，10-09 退避后已收敛为周期低频告警，非新增开销。

## 四、折算收益区间与不确定性

**能耗折算（Q1）**：2.15 core-hour 按各簇单核边际功率（簇表功率 × 1/核数）折算：
- little@2016000：0.933W/4=0.233W → 0.50 Wh；big@940800：0.654/4=0.164W → 0.35 Wh；big@1516800：0.475W → 1.02 Wh；little@307200：0.017W → 0.04 Wh；prime 单核算力边际按 1 核簇=3.08W → 6.6 Wh（不现实，daemon 无 prime 钉定，仅作上界离群值剔除）。
- **区间：0.15 ~ 1.1 Wh，中枢 0.35~0.65 Wh**（≈整机放电 66.5Wh 的 0.2%~1.7%，中枢约 0.7%）。分批 0.034~0.273 Wh。
- 不确定性：表为纯动态项且电压借自另一批次（绝对量系统偏差）；daemon 线程实际落簇/频率未逐秒归因（息屏跑 little 低频、亮屏偏 big 中频的假设未验证）；漏电/静态未计 → 真实值可能高于中枢。

**各建议收益（纯自耗口径）**：
- #1+#2（@S 分片+尖峰让路）：作用于亮屏 6460 核秒中的构建份额。若 p50 段（贴阈值的常态构建）压缩 30~50%，对应 **0.10~0.30 Wh**（占自耗 15~45%），并消掉大部分 4403 告警里的 p90+ 段。不确定性：构建占 daemon CPU 份额未单独测量（需 B 的 selfcost_*.log 桶数据落地后精化）。
- #3（cpuset 交集校验）：能耗收益小（5355 次 syscall 级，<0.005 Wh），收益在**消除无效重试与 @A 噪声**、提高诊断信噪比。
- #4（滚动归档）：能耗收益 ≈0，数据连续性收益 8 次/33h 断档归零。
- #5（无变化 tick 短路）：息屏 1206 核秒若压 20~40% → **0.01~0.05 Wh**（小但息屏场景占比高）。
- **自耗总可压缩量估计：0.15~0.40 Wh（自耗的 20~55%）**，同时告警量预期减 50~80%（#1+#2 主导）。
- 不确定性总源：① 功率表口径（纯动态、借电压）；② build/tick 份额拆分缺直接测量（待 10-07 计划 B 阶段 selfcost_*.log 数据）；③ 单批时长不均衡（1011-000901 仅 1h，批级 corr=0.48 样本小）。
