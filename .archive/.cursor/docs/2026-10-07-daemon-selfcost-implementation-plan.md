# daemon 自耗归因实施计划（修订版）

> 状态（2026-10-07）：**已废弃**——本修订版已并入 `.cursor/plans/2026-10-07-daemon-selfcost-implementation-plan.md`（合并版，唯一有效计划），本文件仅存档。后续进度以合并版与台账 07 为准；阶段 B/C(部分)/D1 已实施（未验证），见 `.trae/docs/2026-10-07-selfcost-phase-bcf-results.md`。
> 执行时使用 writing-plans / executing-plans 技能逐阶段核对；每阶段都需取得对应授权。不得自动创建 worktree、安装依赖或提交。

**目标：** 区分进程总 CPU、调度线程分块 CPU、同步墙钟耗时与未归因部分，形成可复算的成本明细；不承诺 CPU 或功耗降幅。

**架构：** 先校正离线分析工具的时间、身份和覆盖口径，筛选候选；再在原同步路径做最小直接测量并固定基线。诊断线程化只进入后续独立设计，不混入本专项实现。

**技术：** Python 标准库、现有 devimp CSV/日志、Rust 标准库 `Instant`、Android/Linux 线程 CPU 时钟；不增加第三方依赖。

## 2. 本次审查修正

1. P1≈26 / P3≈29 / P2≈86 ms/s 是跨场景推导的量级提示，不是测量基线，也不是验收目标。
2. 30～40ms 是进程 CPU 配对估计，不是调度墙钟阻塞；不能从 `Instant` 墙钟测量直接扣除进程 CPU。
3. 仅记录 ≥50ms 的 debug 行会遗漏主体分布，不能建立基线。阈值只限制额外告警，所有调用必须进入汇总。
4. 删除原 P0-3 的 `aff_secs>1` 新对照包要求：这违反不降低采样质量约束。既有非默认样本可分层分析，但不能为本专项修改采样配置。
5. 原 P0-2 的主动关闭 devimp 对照不属于当前可执行范围：不停止既有采集，不做开关实验。可使用已有且有显式状态证据的自然关闭窗口；没有则报告不可识别。
6. 离线候选筛选不依赖设备补采或源码测量，先开展；直接测量是严格分块归因及迁移基线的前置，不是整个专项启动的前置。
7. main 日志首尾之间有覆盖不证明全程诊断开启，覆盖之外也不证明关闭。归档、轮转、缺日志与关闭必须分开。
8. 跳帧配对的负差不能单独证明选择偏差，更不能证明“系统忙导致跳帧”；该因果解释保留为假设。
9. 缺少 status 秒数不等于丢行率或繁忙导致漏写；需区分挂起、停机、归档、缺文件和未知缺口。未知缺口不补零、不外推。
10. 方案里的 ≤0.05% 合计及 1～3ms 微优化量级不是直接测量的上界，不用于投入排序或验收承诺。
11. 缓存 policy 60s 才发现增删不是严格输出不变；不纳入本专项。电池 TTL 同样单独授权，不能顺手做。
12. 诊断线程发布一致上下文仍不保证实际 stat 读取时点不滞后，迁移必须单独验证采集时延，不能预先宣称不降质。

## 4. 阶段 A：校正离线工具，再筛候选

### A1 输入与身份

- [ ] 将硬编码 CASES 迁移为显式输入清单，CLI 采用必需的 `--manifest` 参数；保留 `feas` / `diag` / `pair` 子命令，无参数或未知子命令明确报错，不回落到feas。
- [ ] 清单每项包含 `case_id`、`status_path`、`devimp_dir`、`aff_path`、`version_identity`、`config_identity`、`session_id`。路径相对项目根解析，拒绝重复 case_id。
- [ ] 输入文件不存在时明确失败；身份不可取得时记录 unknown，禁止跨 unknown 分组比较。不要求重新解压已有包，不覆盖原始文件。
- [ ] 用 `csv.DictReader` 按字段名取值，不用 `q[23]` 等固定下标。必需字段为 timestamp、type、mode、package、screen_prop、clg_active、daemon_utime_ms、daemon_stime_ms；缺字段或非法数值报告原因与条数，不静默跳过。

当前脚本读取 `q[5]` 的 screen_on，而既有自耗报告按 screen_prop 分层；修订后 screen_prop 作主层，screen_on 只保留辅助字段，二者冲突单列。

### A2 时间与差分

- [ ] 每个源文件按顺序展开跨午夜时间；时间回退无法区分午夜与重启时标记 ambiguous，并终止该连续段。不同文件和进程会话之间不做差分。
- [ ] aff 帧保留日期、源文件、出现序号和重复秒内的所有帧，不再用 `set(sec)` 或字典覆盖。日期缺年份时与清单和 status 顺序核对，不靠时分秒全局拼接。
- [ ] 双端身份、type、mode、package、screen_prop、clg_active 一致且 CPU 计数非递减，才进入同层差分；任一变化切段。无证据识别的重启/重置不得跨越。
- [ ] 定义 strict-second 层为 dt=1s；另外报告 short-interval 层 0<dt<10s，按 `sum(delta_cpu_ms)/sum(dt_s)` 计算。两层独立，不把所有间隔当一秒。
- [ ] 移除无依据的 delta_cpu≤3000 过滤。异常差分先单列；如需要上界，依据已知逻辑 CPU 数与实际 dt 校验，缺拓扑时不擅自截断。
- [ ] 稳定段覆盖用有效间隔时长，而非行数。输出各层有效时长、文件跨度、缺口数/最大值、边界排除时长、重复/非法/重置条数；不可解释时间不纳入均值。

### A3 诊断证据与配对

- [ ] `diag` 输出 confirmed_on / confirmed_off / unknown。明确开关事件或配置证据才能确认关闭；只有日志首尾时只能报告文件覆盖证据，不填满中间秒作为确认状态。
- [ ] `pair` 三个 status 端点必须在同一严格连续层；保留所有帧，拒绝多帧或相位不确定窗口。输出差值和证据限制，不根据差值符号自动断言原因。
- [ ] 对照 @S 位于 status 写出之后的调用顺序，允许按候选相位作敏感性分析；秒级时间戳不能唯一归属的配对标记 ambiguous，不强制当下一秒成本。
- [ ] `feas` 将 package/mode/clg 等分层和线程规模、日志活动分开报告。tick 落行数只称日志活动，不推导执行次数。
- [ ] 输出长段（≥60s）和全部有效短段两套覆盖，不因不足60s便抹掉全部证据；没有可比样本时结论为 insufficient，而不是0。

### A4 测试与离线验收（将来授权后）

- [ ] 新建测试用例：跨午夜、重复秒、多帧同秒、计数重置、模式/包/屏幕/clg/type 切换、缺口、空文件、缺字段、未知身份、main 文件首尾有洞。
- [ ] 测试断言：边界不进入差分；2s 内20ms计为10ms/s；3行严格一秒段覆盖2s而非3s；两帧不合并；日志之外状态为unknown；负配对不输出因果结论。
- [ ] 测试授权后运行 `python3 -m unittest discover -s scripts/devimp -p 'test_selfcost.py'`，全部通过才使用修订算法。
- [ ] 分析授权后执行 `python3 scripts/devimp/dvselfcost.py feas --manifest .cursor/docs/2026-10-07-daemon-selfcost-inputs.json`；另两条命令只将feas替换为diag、pair。输出保存到本环境结果文档，清单中的路径必须在A1核对，不用硬编码 CASES 猜测。
- [ ] 验收报告将旧算法复现与新算法差异并列；每个数给出 case/session/版本/配置、有效时长和排除原因。旧数不一致先解释，不改算法去迎合旧数。

阶段 A 交付：可复算的样本覆盖与候选清单；无诊断关闭证据就保持“非诊断成本未知”。此阶段不承诺分块执行次数或CPU残差已查明。

## 5. 阶段 B：原同步路径的直接测量

启动条件：阶段 A 交付已评审，用户单独批准测量实现。不得因本计划完成就插入计时。

### B1 测量定义

- [ ] 区间采用相邻四个墙钟端点：before_build、after_build、after_write、after_summary。build与write分别记账，总同步成本覆盖前两段；summary另记，不算进build。
- [ ] build/write 同时用当前线程 `CLOCK_THREAD_CPUTIME_ID` 两端差分记 CPU；读取失败记 unavailable 和错误次数，不用0替代，不用进程时间兜底。
- [ ] 累计结构每段保存 count、cpu_valid_count、wall_ns_sum、cpu_ns_sum、wall_ns_max、>=50ms次数及固定墙钟直方图。直方图边界为1/2/5/10/20/40/50/100ms，每桶含其上界，另有超界桶；分位数仅报告桶范围，不冒充精确p95。调用无有效CPU读数时仍计入wall/count，cpu_valid_count为0时CPU均值输出unavailable。
- [ ] 每次调用都入累计，≥50ms只控制节流warn/debug，不能控制是否记账。不读取额外 `/proc` 作为每帧计时器，不在累计器内持有全局锁。

### B2 输出与生命周期

- [ ] 累计器由同步采集所属线程独占。仅 diag_active 且实际采样时计时；诊断关闭时不继续探测，不能改变现有门控。
- [ ] 摘要每60s或诊断会话结束输出到 logger 管理的独立 `selfcost_*.log`。必须沿用现有 devimp 目录、轮转和归档预算路径，不能产生无界文件；现有格式不变。
- [ ] 摘要字段固定为 schema、session、window_start/end、block、count、cpu_valid_count、wall_ns_sum/max、cpu_ns_sum、wall_buckets、slow_count、clock_errors、write_errors。记录测量schema和配置身份，不把新样本与旧版本混合。
- [ ] CPU区间不重叠，外层总区间不再作为额外可加项。计算均值为sum/count，CPU均值为cpu_sum/cpu_valid_count；会话结束输出不足60s的尾窗。
- [ ] 测量失败不阻断原采集或调度。摘要落盘失败明确告警并报告测量不完整，不丢原aff帧以保摘要。

### B3 归因与验收

- [ ] 先只覆盖@S build/write，不同时修改 token、缓存或线程归属，避免基线变动。
- [ ] 汇总同会话、同窗口的进程CPU与被测线程块CPU。仅在CPU读数完整、时间窗和边界可对齐时给出部分账；墙钟绝不从进程CPU中相减。
- [ ] 与其它线程的未测CPU、测量本身和摘要写入成本区分；负残差保留并调查，不截成0。不将eBPF系统事件路径成本归进本账。
- [ ] 用户恢复测试授权后，在 diag_cost.rs 增加确定性累计/直方图/错误路径测试；覆盖全部调用计数、分母、尾窗、重置与失败不污染基线。Android目标检查命令为 `cargo check -p chiri --target aarch64-linux-android`。
- [ ] 本地编译测试继续被用户跳过时，只交付静态审查状态，不能标记目标检查通过。真机采集另需设备授权，不主动关闭dev_record或调大aff_secs。
- [ ] 固定迁移前输入清单、版本配置、分层CPU统计和墙钟分布后，再讨论第二批候选块。候选块必须先核对执行入口、线程归属和嵌套关系，每批只增加少数点。

阶段 B 交付：测量实现及其未验证项、迁移前基线、仍未归因账。没有设备测量时只能交付实现，不能填入真实成本。
