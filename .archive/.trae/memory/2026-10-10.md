### 改动（`.github/workflows/build.yml`，步骤重编号为 1~13）

   （含 `-Z build-std` 的 core、eBPF OUT_DIR 产物）。key 含 rustc 版本 + Cargo.lock，
   nightly 更新或依赖变更自动冷启一次。
2. **cargo-ndk 换预编译二进制（原步骤 7 拆为 8/9）**：新增 `Setup NDK environment` 单独

   `cargo-ndk-x86_64-unknown-linux-gnu-*` asset 下载解压后 `install` 到 `/usr/local/bin`。
   与 bpf-linker 同一套写法（带 GITHUB_TOKEN 防 rate limit、`curl -sSfL` 暴露真实错误）。
3. **`paths-ignore`（push + pull_request）**：`docs/ agentsdocs/ mdocs/ .archive/ .trae/

### 落地前实测核验

- `bbqsrc/cargo-ndk` v4.1.2 确有 `cargo-ndk-x86_64-unknown-linux-gnu-v4.1.2.tgz`（2.4MB）；
  **tgz 内套一层同名目录**，故用 `find -name cargo-ndk -exec install` 定位（同 bpf-linker 写法）。
- **该二进制拒绝直接执行**（`This binary may only be called via \`cargo ndk\``），
  校验行必须是 `cargo ndk --version`（实测输出 `cargo-ndk 4.1.2`）。
- asset 选择 one-liner 对真实 API 跑通；`yaml.safe_load` 校验通过、步骤编号 1~13 连续。
- 未采用 `taiki-e/install-action`：cargo-ndk 不在其 TOOLS.md 托管清单内，会走
  cargo-binstall 回退（asset 命名带 `v` 前缀，匹配不确定），不如手写下载可控。

### 明确不做（避免反效果）

- **不吃 NDK 缓存**：那 29s 大头是 GitHub 内网下载，而解压后近 1GB，缓存上传/恢复基本抵消。
- **不加 webui npm cache**：依赖安装仅 3s。
- **不减 fetch-depth**：`xtask/src/main.rs` 用 `git rev-list --count HEAD` 算版本号，需全历史。
