## 任务：修复非 ChiRi SoC 无法使用 devimp

用户诉求：「修复在非 ChiRi soc 上无法使用 devimp 的问题」；补充「也有可能是开了 down 之后
devimp_main 也被停了，反正 devimp_main 必须能够始终独立开启」。经确认范围：**解耦写入，非 ChiRi
也产 main_ + aff_ 线程流**（不改 WebUI，LogsView 有文件即显示；不加无关开关）。

### 根因定位

- devimp 全部写入点在 `src/chiri/mod.rs` 的 `scheduler_ipc` 1s 块内；非 ChiRi 不启动调度线程 →
  一行不写。
- 排除误判：ChiRi 真 DOWN 时 1s telemetry/devimp 块未被 `!halted` 门控，devimp 照常写；用户感知的
  「down 把 devimp 停了」实为「非 ChiRi 本就不写」的表象。

### 改动

- `src/chiri/mod.rs`
  - `build_aff_snapshot` 与 `AffinityManager` 解耦：签名改
    `(th_diag: &[(i32,i32,i16,bool)], managed_pids: &[i32], fg_pid, fg_pkg, top_n)`；ChiRi 调用点先
    `thread_diag()/managed_pids()` 再传；非 ChiRi 传 `&[]`（仅 top-N 进程 + 前台线程）。
  - 新增 `pub fn start_diag_thread(config_path: PathBuf)`：独立 1s 诊断线程（`diag_writer`），每 5s 重读
    `meta.dev_record/devimp_top_n`；关闭态零采样零 IO。每秒写 `main_snap` + `aff_snapshot`，屏幕/模式
    变化写 `main_event`（首帧只建基准）。只读快照、不碰 sysfs。
- `src/main.rs`：非 ChiRi 分支起 `chiri::start_diag_thread(config_path.clone())`，成功/失败各打一条。
- `src/monitor/mod.rs`：telemetry 线程去掉 `is_chiri_soc()` 门控，全 SoC 启动（`main_snap` 数据源）。
- `src/logger.rs`：`note_write` 过时注释更正（非 ChiRi 现已产 devimp，但仍不自动重启）。
- i18n：新增 `main-diag-thread-started` / `main-diag-thread-failed`（zh/en）。

## 任务：TypeScript 7.0.2 升级评估（结论）

根 `typescript` 须保持 5/6 版本区间（svelte-check 的 peerDependencies `^5||^6` 与内部 `major < 7`
校验）；实际类型检查走 `@typescript/native` alias + TS 7.0.2 + `svelte-check --tsgo`。升级根
`typescript` 会致 `npm install` ERESOLVE 与 svelte-check 运行失败，无可用 svelte-check 版本支持 TS7 →
只能等上游放宽。Dependabot 应忽略根 `typescript` 的主版本更新（避免 PR #5 之类的反复失败）。
