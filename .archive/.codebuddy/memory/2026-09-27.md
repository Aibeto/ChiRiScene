## 当日复核（用户追问「重新确认发现了什么问题」后重验，一处结论有修正）

- **shebang 那条有物证，且不是首次引入**：`devimpbin/bak/module__action.sh` 首行就是 `# !/system/bin/sh`（已被合并的残骸）→ 这个坑**以前踩过**，原 `tmp_reflow` 的「shebang 绝不改动」注释就是为它打的补丁；我移植时把补丁错放进 `.py` 分支 → 属**复发**，非新 bug。工作区 4 个 `module/*.sh` 首行均为正常 `#!/system/bin/sh`，无需修复。
- **`strip_code` 失明定位到根因（此前只是推断）**：非 py 分支只认 `"`，不认 char 字面量。`src/down.rs:47` 的 `c == '"' || c == '\''` 让状态机进入字符串 → 该文件 7 行注释未被剥。最小复现：`let x = 1;` / `/// A` / `let c = '"';` / `/// B` → 输出里 A 被剥、B 没剥。其余 strict 差异文件同样带未剥注释行（meta.ts 7 / paths.ts 6 / lab.ts 21 / mock-shell.ts 3 / ConfigView.svelte 12 / service.sh 2）→ 上一轮「strict 假阳性」得证。修法留了 `TODO: `（进字符串前先判 char 字面量）。
- **`module/action.sh` 那条差异不是代码改动**：块掩码口径报 `+#!/system/bin/sh`，是「快照里 shebang 坏、工作区已修好」的痕迹；上一轮把它算进「6 个真代码差异」不准确。它此前不报是因为初版 block_view 对 .sh 也没做 shebang 保护（两侧都被 mask），修保护后才浮现。
- **使用口径（已写进 docstring）**：`audit` 反映「快照以来的一切差异」，隔了后续编辑就分不清哪些是排版造成的；要证明某次排版没动代码，须在 reflow 前后紧邻着看——真正的保证来自 reflow 的构造（只重写注释块区间 + `comment_skip` 跳过 shebang 与 python 字符串行），audit 只验证块识别没误伤。
