# 决策时延取证埋点（2026-11-22 落地）

> 目标口径（用户 2026-11-22）：**降低决策时延与抖动**，不是省电。带「即将发版」约束：本版只加零行为影响的计时埋点，语义改动留到下版本，等新包真机日志定夺。不做同版本 A/B，跨版本同场景对比即可（同 SoC + 同 kernel + 同 `exe` 指纹）。

## 一、为什么先取证

PGO 采样包 `devimpbin/logd_1122-160240.tar` 的 9 轮 `cfg=sm8550` 实测（549 s 墙钟 / 49.2 CPU 秒）给出三个绝对量级：

| 项 | 占 chiri 自身 CPU | 绝对值（单核口径） |
|---|---|---|
| 逐线程 `/proc/<pid>/task/<tid>/stat` 扫描 | 10.8% | ≈0.97% |
| 唤醒/调度（`__schedule` 532、`finish_task_switch` 767） | 25.3% | ≈2.3% |
| `dumpsys` 子进程 | 6.4% | 不计入 chiri 自身 |

chiri 自身只占单核约 9%，**省电论据弱**；真正的论据是决策路径的延迟与抖动（`scheduler_ipc` 线程 22.4% 样本、其中大量 `futex_wait`/`finish_task_switch`，内核侧还有 `cgroup_freezing` 229 条）。故先量「迟到多少、忙多久、慢的时候后台是否正在扫」再决定改什么。

## 二、埋点设计（`schema=latency/1`）

新模块 `src/chiri/diag_latency.rs`（503 行），只读时间戳与原子计数，**不改任何判定分支**。输出写进与 selfcost **同一个** `devimp/selfcost_<ts>.log`，按行首 `schema=` 分流；60 s 一窗，只在诊断会话内累计与落盘（诊断关闭/停机冲刷尾窗，与 `aff_cost_session_tick` 同门控）。

| 轨道 | 含义 | 钩子 |
|---|---|---|
| `wake` | 调度线程**定时唤醒迟到量** = 实际等待 − 请求等待；只记超时唤醒，请求等待 <1 ms 的轮次跳过 | `src/chiri/mod.rs` 的 `rx.recv_timeout` 超时分支 |
| `work` | 收到一条事件到下一轮循环开头的墙钟 | 事件循环顶部 |
| `scan_fg` | `fg_thread_max_util` 逐线程读 stat 的耗时 | `src/monitor/cpu_monitor.rs` |
| `scan_procs` | `snapshot_procs` 全系统进程快照 | 同上 |
| `probe` | 单次 `dumpsys` 查询墙钟（含 fork/exec、读取、回收） | `src/monitor/window_visibility.rs` 的 `collect_one` |

行格式：`schema=latency/1 session=s<epoch> window_start= window_end= track= count= sum_us= max_us= p50_us= p95_us= p99_us= ovf=`；`wake`/`work` 追加 `slow_us=10000 slow= slow_scan= slow_probe= slow_both= slow_neither=`。

**慢样本相关性**：在慢事件发生的**那一瞬间**读 `SCAN_INFLIGHT`/`PROBE_INFLIGHT`，四类互斥计入，合计等于 `slow`。这是用来区分「卡顿由后台探测引起」与「卡顿另有来源」的唯一线索。

口径与坑：
- `p50/p95/p99` 取直方图上界（50 µs~200 ms 共 12 档 + 溢出桶），偏保守，不可当精确值；`ovf` = >200 ms 样本数。
- 空轨道不落行：**缺行 = 该窗口无样本，不是 0**。
- 计数与直方图多线程并发自增，窗口切换瞬间 ±1 条样本可能落进相邻窗口，跨窗口求和不强求一致。
- 崩溃恢复路径清空 `last_recv_at`，否则 1 s 退避 + 接管重建会被记成一条超长 `work`。

## 三、下版本待改（已入 `agentsdocs/07-todos.md`）

1. **`/proc` 逐线程扫描**（证据最强）→ 改用 eBPF map 的线程级 util（`compute_thread_level_util` 已走 BPF，不读 stat）。判据：`scan_fg` 与 `slow_scan` 同步下降，FAS 选线程结果不变。
2. **`dumpsys` 探测合并** → 同一 tick 复用一份输出（`collect_snapshot` 已把两段拼在一次读取里）。前置条件：activity/window 判定逐条不变（含 800 ms 超时行为）。
3. **定时唤醒合并** → 单线程截止时间队列（事件循环的 `until()` 已是该形态）。前置条件：任何一路采样时点不后移。
4. **PGO 采样 `--no-inherit`** → 去掉继承的 dumpsys 子进程样本（约 6.4%），纯粹化热度；不影响运行行为，可与第 2 项一起定。

约束不变：决策签名 / 采样频率 / 字段数不减；禁并行/交错 A/B；验收只认跨版本同场景的 `latency/1` 分位 + `slow_*` 占比，**不能用 main tick 行间隔代替**事件入队到处理的墙钟。
