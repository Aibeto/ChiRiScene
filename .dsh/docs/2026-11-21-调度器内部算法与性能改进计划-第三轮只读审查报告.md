## 2. 逐项审查结果

### 2.1 P0 FAS 写频失败状态污染

**Verdict：核心缺陷成立；恢复范围与 QoS 解释需拆分。**

- src/scheduler/fas/policy_controller.rs:145-151 调用 min/max FastWriter 后忽略 bool 返回值，:152-155 仍推进 current_freq、hold 和 verify 目标；:156-159 的 verify_at 只在 changed 或初值为空时更新。
- src/utils.rs:445-451 的 EACCES/EROFS reopen 每个 writer 生命周期至多一次，构造时也可能消耗机会；:517-519 的 re_unmount 只 umount；:529-570 写入可返回 false。不能从一次 reopen 推导通用恢复上界。
- src/scheduler/fas/policy_controller.rs:286-292 只读 max scaling 值，无法覆盖 min/max 半写组合；:222-226 的 actual<expected 会归类 qos_clamped，:306-312 的 force_reapply 在此状态可能提前返回。失败写与 QoS/thermal 钳制不是同一种证据。
- reset 的 :314-319 与 policy_mgmt init 的 :444-445 也需要覆盖。现有 controller.rs:508-529、:653、:668、:812-813 的 /nonexistent 测试依赖假成功语义，须迁移到显式 fake writer。
- 已写入计划的处理：区分 min/max write result、max/min/current readback 与 verified；覆盖 init/apply/probe/tamper/force/reset、raise/lower 半写和 fd 重建生命周期；不预设统一恢复上界。实现前必须定义 current_freq 是命令目标还是最近成功写入值。

### 2.2 P1 EEM ELF32 预检拒绝

**Verdict：拒绝路径缺陷成立；不得与 ledger 预提交或普通 abort 合并。**

- ELF32/AArch32 gate 在 src/chiri/affinity.rs:1231-1243，调用点 :2726-2728 是 naked continue；预算在 :2680-2684 已消耗。它不同于 dst_empty 的 :2702-2724 abort 路径。
- src/chiri/placement.rs:504-519 在写前更新计划窗口/簇/ledger。:512-516 明确为预算有界预提交；预提交本身不等同本缺陷。aarch32_clusters 默认空时 gate 会放行；两拍 old∪new 可能第一拍通过，纯不兼容下一拍才被拒。
- 部分 clipped readback 会调用 note_applied 并清 fail_streak；None、Some(empty)、非连续回读与外部 moved_group/eem_window/eem_cluster 状态不可互相代替。补 abort 不会自动修复下一轮 Subject 锚点，cgroup move 成功也不回滚。
- 已写入计划的处理：独立定义预检、预提交、engine/eem_window/Subject 锚点及非诊断拒绝计数；测试 default-empty、两拍、readback 各种形状和 0→1→0 streak 循环，保留 cgroup 与 transition 语义。

### 2.3 P1 scenemode prime 成员

**Verdict：遗漏事实成立，入口/退出意图及周期风险部分成立。**

- src/chiri/mod.rs:4442-4448 与 :4498-4505 的 fold 都只遍历 little→big；src/common.rs:277-305 返回 little/big/prime 三段。module/config/sm8750/soc.yaml:22-24 对应 little 0..0、big 0..6、prime 6..8。src/chiri/core_ctl.rs:980-985 提供三段遍历对照，但不能单独证明两个 scenemode fold 意图相同。
- 进入门 :4453 的 long_off 分支跳过 load gate，退出门没有同样跳过；若补入 prime 改变饱和判断，约 10s 退出与 300s cooldown 的周期是静态算术风险，不是测量结果。不要写成确定拉锯。
- 已写入计划的处理：入口/退出集合分别确认；检查 prime 索引、60s precheck、delay 60/3000、long_off=4×delay、计时器复位和多周期行为。拓扑 OnceLock 冷启动与稳态 fold 分开，不缓存集合或改机型配置。

### 2.4 P1 EEM allowed 与窗口规划域

**Verdict：per-core 规划缺口成立；原“syscall 前没有交集”描述不成立。**

- src/chiri/placement.rs:298-306 的 cluster_pool 来自拓扑；:207-211、:256-269 在整簇池选择窗口，decide 没有 per-core allowed 输入。Window::new/cores 在 :47-57 假定连续区间。
- src/chiri/affinity.rs:2698-2701 已在 syscall 前将动作意图与 allowed 相交；:2702-2724 处理空目标。因此问题不是没有 syscall 交集，而是规划域、成本、ledger、anchor 与实际写回可能分叉。:2726-2728 的 mask_write_allowed 拒绝不 abort。
- allowed=None 在 :2550-2551 解释为 online_all；当前 cpuset 读取路径把 unknown 与 readable-empty 混合为 None 的行为需以三态定义，不声称 Some(empty) 是当前可达状态。非连续 allowed 不能塞入一个连续 Window。
- 已写入计划的处理：逐核验证 plan/commit/from/to/applied/eem_window/ledger；定义 Unknown/Empty/Cores、宽度大于连续段的处置，并保留失败写锚点/backoff。P3 只负责缓存成本。

### 2.5 P1 CLG 扫描

**Verdict：条件性重复扫描部分成立，扫描触发器原描述错误。**

- src/chiri/cpu_load_governor.rs:212-228 的 max_util/high_zone_hits 遍历 affected_cpus；:565-584 还计算 max 与 over/under。通常约 2A。
- 额外扫描只由 :656-660 guard 触发：count>0、gate>0、old_perf>=gate、candidate>old_perf+1e-6；:670 的 hits>=need 是扫描结果，不是触发条件。A=affected_cpus.len，P 是有效 core_utils 索引数，hits<=P。need 取 self.cfg.count，而 gate/hits 用 eff_cfg。
- all-NaN、短 core_utils、缺索引、阈值零、hold 与比较符都影响结果；不按 core_utils.len 或在线核数归一。worker stop 修复已在 HEAD，不复做旧 +15 行/lost-packet 建议。
- 已写入计划的处理：按 A/P 和 decision/timeout/diag/EEM 分层，新增版本化 clg_zone，旧日志缺字段标 unknown，不补零，并保持 status 28 列。

### 2.6 P1 telemetry/status 同步成本

**Verdict：同步路径成本存在，线程化收益尚未证明。**

- 正确 ledger 在 src/chiri/diag_cost.rs；src/chiri/mod.rs:3236-3238、:3372 与 :3399-3419 是不同门控/写入点，:3245 是频率解析而非总 gate。DIAG_WORKER_ENABLED=false 使默认 worker 分支不可达；src/monitor/telemetry.rs:232 是独立线程。status 即使 DOWN 仍运行，diag session 更新周期约 2s。
- src/logger.rs:585-624 的 status writer 持锁，两次无缓冲 write_all、有限 reopen/metadata 检查；28 列顺序在 :740-767；PowerAVG 另走 tmp+rename/fallback。没有证据把所有成本归到同一 sink。selfcost 的 1–100ms wall bucket 对微秒成本分辨率不足，self_cpu_ms 是进程级而非调度线程。
- 已写入计划的处理：分开节点读、格式化、status、PowerAVG、独立 monitor；保留 sample/write 时间、身份与过滤顺序、PowerAVG 状态、DOWN 写入和 28 列；队列不得静默丢样。线程化必须先过调度线程 CPU、IO 顺序和尾延迟基线。

### 2.7 P1 heavy/loading 长帧

**Verdict：窗口边界问题部分成立，“静默漏采样”概括不准确。**

- src/scheduler/fas/frame_pipeline.rs:315-384 的顺序是 stale reset、warmup、app-switch、heavy/loading、long-frame。150–500ms 路径刷新 last_frame_at 后早退，造成 false-fresh/窗口饥饿；>500ms 路径不刷新，可能反复 stale→warmup=12。两者不能合并。
- long-frame 分支还需满足 heavy>=fixed_max、fixed_max<app_switch_gap 等条件；默认配置下是否可达未测。SystemLoadUpdate/on_load_update 仍可能单独推进 thermal/apply，不是整个控制链停摆。
- 已写入计划的处理：覆盖 150/500/3000ms 边界、300ms×20、600ms×60 后恢复、warmup、gear 表外 target/runtime config，并分别检查帧域与系统负荷 writer；不降低采样。

### 2.8 P2 focus 证据重复

**Verdict：重复读取成立，缓存可跳过的成本被 fast_same 限制。**

- src/chiri/mod.rs:264-421 的 reconcile_fas_focus 有七个调用点；FrameUpdate 调用是 :4575，:4578 是 FasManager::on_frame。:4569-4570 已取 foreground snapshot/raw，fast_same :293-315 仍做 clone、liveness、锁/clone、fas_package_ready 和状态副作用。
- owner_allowed 每次重算，不可直接缓存。ConfigReload :4589 无 probe invalidate；request revision 是发布保护而非证据版本。Frame feedback freshness 为 500ms，窗口证据/观察 TTL 也有各自上限。
- 已写入计划的处理：先测七点分母与证据年龄；优先评估把 FrameUpdate 已有证据传入 reconcile，不跳过 fast_same 副作用、不缓存 owner_allowed，不与 pidfd 重复计固定前缀。

### 2.9 P2 频率迟滞坐标

**Verdict：坐标混用部分成立；修复会改变带宽，不能当纯优化。**

- src/scheduler/fas/policy_controller.rs:71-77 使用 (f-fmin)/max(fmax-fmin,1.0)，:133-135 取当前比率。src/scheduler/fas/policy_mgmt.rs:261-276 的旧式 diff 与写入目标邻近查表存在坐标和离散频点两种误差。
- 对 D=max(fmax-fmin,1.0)，当 fmax>0 时一般坐标差为 C-A=(f*D-fmax*(f-fmin))/(fmax*D)；仅当 fmax-fmin>=1 时才化简为 fmin*(fmax-f)/(fmax*D)，fmax=0 时旧坐标未定义。此外旧 numerator nearest(ratio) 与真实写入 nearest(adj) 可不同。统一坐标后同一个 h 从约 h*fmax 变为 h*D 的有效带宽；当 fmax>0 且频差>=1时缩窄比例为 fmin/fmax，max(1.0)保护生效时另按 D/fmax 比较。这属于控制语义变更。
- reviewer 确认 current_freq 按构造来自频点表；空/乱序运行期输入不可凭空假设。find_nearest_freq(NaN) 会落到最低频，需锁定现状。已写入计划的处理：分开偏差组件、重放 false_write/false_skip 与 kHz 带宽，未获书面语义接受不得统一坐标；若行为差均为零则退出性能序列。

### 2.10 P2 scenemode 事件成本

**Verdict：迭代器零分配成立，主要收益未证。**

- src/common.rs:277-305 返回栈上 range；src/chiri/mod.rs:4443-4448、:4498-4505 稳态 fold 无 heap。首次 OnceLock YAML 解析可能分配；:4428 mode String clone 有分配，:4436 HashMap clone 仅 map 非空时分配；entry reload/apply 可能比 fold 贵。
- 仅 screen-off 60s 后的事件相关；不能套每帧阈值或 1ms wall bucket。已写入计划的处理：按 SystemLoadUpdate 事件率拆冷启动、entry apply、clone、active-exit fold；无显著 thread CPU 直接结项。删除无测量的缓存与 big⊃prime fallback。

### 2.11 P2 FAS policy 数学

**Verdict：每 tick 有计算，收益很小且部分分支条件化。**

- src/scheduler/fas/policy_mgmt.rs:175-188 重算输入，:261-266 sqrt/powf/blend；:270-272 第二次 nearest lookup 仅 target!=current 时到达。hold :242-259 可提前退出。频点构造已有排序/去重。
- find_nearest_freq 空表可能越界，但 policy_mgmt caller 对空表有 continue；需先证明可达性，不能把不可能的运行输入写成热路径优化。
- 已写入计划的处理：按 policy/tick 测量、检查非空升序构造不变量、覆盖 w/NaN/fmax=0/QoS/force/hold；只考虑构造期稳定量，动态 thermal/ceiling/demand 不跨 tick 缓存。迟滞坐标修复必须独立审批。

### 2.12 P2 EEM/affinity 分配

**Verdict：分配点存在，原始工作量上界不成立。**

- src/chiri/placement.rs:128-134 effective Vec 仅在 gate 后分配；:55-57 Window::cores 可在无迁移候选中分配。src/chiri/affinity.rs:2554、:2581-2586、:2612、:2639、:2698 还有 pool/filter/window/mask 临时容器。
- budget=4 只限制发出的 Some(action)，不限制 None candidate 或早退候选工作；因此原“每轮最多400B”没有依据。allowed clone 只在内容变化时发生，需单独计数。
- 已写入计划的处理：按 tick/candidate/decide/action/affinity attempt/成功 syscall 分别计 allocation count/bytes；无 counting allocator 与同输入 decision trace 不做 buffer 复用。正确性仍归 P1，cpuset cache 归 P3。

### 2.13 P2 pidfd poll

**Verdict：窄范围 syscall 成本成立，整体性能优化大概率低收益。**

- src/chiri/mod.rs:4568 gate active FAS，:4575 reconcile，:4578 on_frame；src/chiri/fas_manager.rs:398-410 做 frame 过滤；src/chiri/fas_process.rs:76-78 starttime=None 直接 false，pidfd poll 在 :99-115。poll(fd,1,0) 不阻塞但仍是 syscall。
- 只能省掉被拒帧的 poll；accepted frame 仍需要 liveness。screen/reconcile 是维度而非互斥桶。cfg(test) pidfd=None，须 seam 或真实 child 覆盖 poll。若后续无帧，首个拒绝没有有限上界；不加入无源码依据的 alternative notification。
- 已写入计划的处理：按有序互斥叶桶测拒绝原因与 poll；默认低于实测 >10us/frame 或 0.1% scheduler-thread CPU 门槛则结项，不加逐帧 atomic，保持死亡 owner 保护。

### 2.14 P3 DEBUG 与 gear

**Verdict：DEBUG “未门控”不成立；gear 输入边界需独立验证。**

- src/chiri/mod.rs:4358-4361、:4580-4584 和 src/scheduler/fas/gear_state.rs:320-338 已有 log_enabled!；frame_pipeline.rs:438-459 的 30 帧 heartbeat 不是 FrameUpdate 全局日志门控。
- src/scheduler/fas/gear_state.rs:56-61 reverse-find 对 gear 顺序敏感；src/fas_types.rs:373-393 仅滤非有限/非正值，不排序/去重/设上限；有限 1e30 仍可能进入。PID scale_frames 的饱和与可否归零未测。
- 已写入计划的处理：不以节流降低诊断精度；DEBUG 和 gear 分开。测试逆序/重复/极值/NaN、per-app None/全非法、低于 60 gear 和 PID 多步递减。

### 2.15 P3 cpuset 缓存

**Verdict：miss 分配事实部分成立，净收益未证明。**

- src/chiri/affinity.rs:2478-2506 hit 会 clone；常规双组 miss 的静态结构估算约 5 个 Vec 与 6 个 String heap block，字节数未测；单组/空交集/早退路径不同。:2572 clone 仅在 allowed 内容变化时发生。
- 调用有 pin/force 或 2s rebalance 门；EEM 还有 screen_on、boost、core_utils 等门。1s TTL 短于常规 2s 节奏，稳态命中率预计低；原 160ms/6.25 次每秒口径不成立。
- unreadable/empty raw 与 readable-but-online-empty 的 None/cache 行为不同；allowed=None 在 :2550-2551 fail-open 为 online_all，online_bitmap :675-686 另有 all-true fallback。parser 可静默丢坏 token，min/max 日志不能代表非连续 cpulist。
- 已写入计划的处理：分别统计 unreadable、parse-empty、intersection-empty、single-group fallback、hit、forced call 和 gate-zero；测真实 bytes/open/read/hit rate。不得改 TTL、调用节奏或机型配置。
