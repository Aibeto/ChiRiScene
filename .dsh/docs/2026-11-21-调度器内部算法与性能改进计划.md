# ChiRi 调度器内部算法与性能改进计划

> 状态：已吸收三轮只读审查修订，待逐项授权实施。本文只记录调度器自身的算法逻辑、状态机正确性和程序运行开销，不实施代码或配置变更。
>
> 范围：src/chiri/、src/scheduler/fas/、调度器直接调用的写频/诊断路径。明确排除机型配置、module/config/**、feature.yaml、温控参数、频率阈值和采样降质。

## 1. 约束与已有计划边界

- 本计划不修改 module/config/**、SoC/机型配置或运行参数；发现算法需要配置边界时，只计划代码侧校验、归一化和测试。
- 不减少采样、不降低诊断字段精度、不改变控制周期，不把“行为延迟”包装成采样优化。
- 不做 A/B 对照实验。验证使用离线重放、可控 fake、同版本同场景观察和决策轨迹等价性；不交错运行两个版本来得出收益结论。
- 写入失败、亲和失败、QoS/thermal 限制、旧 owner 和 stale frame 都是有效结果，不能被快路径误判为成功。
- **主路径结果一致性硬门槛：** 对相同有效输入、相同拓扑/cpuset/online/core_utils/频点/owner 快照和逻辑时钟，调度器有序业务轨迹须与基线一致：接受的帧与控制触发、CLG/FAS/EEM/scenemode 决策、目标 gear/频率/CPU mask、状态转换、sysfs/cgroup 写入及回执，以及影响后续决策的状态。内部缓存/数据搬运可不同，但不得改变这些结果；涉及时间窗口时按相同逻辑时间重放，并另验墙钟/尾延迟。
- **允许变化的边界：** 仅明确标注的失败/超时/无效输入兜底分支可改变错误分类、重试/恢复或锚点；正常有效输入和成功下发轨迹必须一致，异常后的下一次正常输入还须回到基线轨迹。不得丢样、降采样或降低诊断数据质量。任何候选只要导致有效输入决策差异，即从本计划排除，不以“正确性修复”或性能收益豁免。
- 进程级 /proc/self/stat CPU 不能作为单线程成本。需要区分调度线程 CLOCK_THREAD_CPUTIME_ID、墙钟延迟、系统调用次数和进程总 CPU。
- 既有 daemon selfcost 实施专项负责自耗计数和诊断交接；本计划只复用其 ledger/闸门，不复制另一套口径。
- 实施任何条目前必须重新读取最终源码和 git diff；不得回退未由本计划产生的改动。本轮第三次复审时 src/chiri/cpu_load_governor.rs 相对 HEAD 无未提交修改，worker stop 修复与测试已在 HEAD；这只代表本轮核对时点。
- 工作区已有 .mnemon/documents/index.json、module/module.prop 等用户变更，实施时不得覆盖或回退。

## 3. 逐项问题、证据和改进方向

### P0：FAS 写频失败会污染控制状态

**问题。** PolicyController::apply_freq_locked 在 src/scheduler/fas/policy_controller.rs:145-151 调用 min/max FastWriter 后丢弃 bool 返回值，:152-155 仍更新 current_freq、freq_hold_frames、verify_freq；:156-159 的 verify_at 只在 changed 或原值为空时更新，并非无条件成功。

**原因与证据。**

- src/utils.rs:445-451 对 EACCES/EROFS reopen 每个 writer 生命周期至多一次；构造时也可能消耗该机会。:517-519 的 re_unmount 只 umount；:529-570 在 file 缺失或写失败时返回 false。调用方不得把 false 当作命令已应用。
- src/scheduler/fas/policy_mgmt.rs:269、:293-295 以 target_freq 与 current_freq、迟滞和 force 分支决定是否再写；伪造 current 会让目标不变时完全跳过 apply，verify 也只在 apply 路径内运行。
- 当前树应以符号 read_scaling_max_freq（policy_controller.rs:约 277-292）为锚：actual<expected 在 :222-226 归类 qos_clamped，:307-309 可能跳过 force_reapply；policy_controller.rs:163-164 的 TODO 还指出只看 scaling_max 无法区分写失败与 QoS 钳制。
- raise/lower 的半写签名不同：raise 方向可能 max 成功/min 失败而被 max 回读掩盖；lower 方向可能 min 成功/max 失败并进入 tamper/rewrite 分支。max-only readback (policy_controller.rs:286-292) 覆盖不了 min/max 半写矩阵。reopen 不是通用恢复上界；失败后 file=None 会使后续写继续失败，须与 writer 重建/reload 生命周期分别验证。
- reset()（policy_controller.rs:314-319）和 init 写（policy_mgmt.rs:444-445）也丢弃写结果，不能只测 apply。

**后果。** apply_freq_locked 在写入 bool 未成功时仍推进 current_freq、hold 和 verify 目标；之后同目标可能跳过 apply。qos_clamped 下 force_reapply 直接返回 (:306-312)，且 force 路径对 min/max 写入结果的处理也需单测。当前证据不足以给出统一最大恢复延迟；必须按失败方向、QoS、目标变化、writer fd 状态和重建生命周期分别推导，不能声称 force 一定恢复。

**量化与快速验证。**

- fake seam 必须区分构造时 init、运行中 writer 失效，并覆盖 apply、300s verify/probe、tamper、force_reapply、reset、policy_mgmt init 六类入口；对 min/max 每方向分别注入成功/失败。
- “成功”分层记录 min/max 各自 write bool、scaling_max_freq readback、可行时 scaling_min_freq 或 settle 后 scaling_cur_freq；当前只有 max readback 已核实。partial/clipped/qos_clamped/verified 必须由各自证据命名，不用单一 bool 代替。
- 逐 tick 记录目标/命令/读回、min/max attempt/result、hold/verify/dirty/write_failed、qos_clamped、下一次尝试时间；dirty 的置位/清除和与 hold、迟滞、force 的优先序必须先写成状态机不变量。记录 force/verify_interval 的生效口径；只有分状态证明了 writer 重建与重试边界后才报告恢复上界，不以“调用方会重试”冒充上界。
- 现有 controller.rs:508-529、:653、:668、:812-813 的 /nonexistent writer 测试依赖假成功语义，必须在 seam 设计中迁移并保留正常控制轨迹。

**计划方向。** 先钉死 current_freq 表示“命令目标”还是“最近成功写入值”，再定义失败状态、write/readback/verified 组合与 dirty 生命周期；apply/reset/init 的失败不得被错误标记为成功。覆盖 QoS、thermal、force、verify、tamper、单次 reopen 和 writer 重建；不预设恢复上界。现有 controller.rs:508-529、:653、:668、:812-813 的 /nonexistent 测试依赖 fake-success，须改成显式 fake writer 结果而不是沿用生产语义。

### P1：EEM ELF32 预检拒绝与回执一致性

**问题。** AArch32/ELF32 可行性门位于 affinity.rs:1231-1243，预算已在 :2680-2684 消耗；调用点 :2726-2728 是 naked continue，未像 dst_empty (:2702-2724) 一样 abort/fail_streak 归属。该拒绝路径不能与空目标集或 promote/narrow 回执混为一类。

**必须拆开的边界。**

- placement.rs:509-519 已先写入 plan.target/window/cluster、ledger 和 step_range，再进入 affinity 落盘；因此 skip 是“承诺已提交、镜像未更新”，不是单纯少一次 abort。每轮 ledger 预提交是 placement.rs:512-516 明示的有界取舍（预算不超过 EEM_MAX_MOVES_PER_ROUND），不等同于 ELF32 bug，也不能假定补 abort 就能收敛。
- :1240-1242 使用 cpus.iter().any；aarch32_clusters 缺省为空（config.rs:1538-1540）时完全放行。两拍动作掩码可能是旧∪新，第一拍含任一可行簇时会写入并被内核摘核，第二拍纯不兼容目标才 skip。
- ELF32 gate 仅对已识别不兼容簇生效，禁用位宽检查或空簇表会绕过；两拍 old∪new 可先通过，后续纯不兼容目标才被拒。readback None 与 Some(empty) 在当前路径落入 unknown；非空 clipped 会 note_applied 并清零 fail_streak。cgroup move 成功后 abort 不回滚已完成的 move。
- plan.target、dst_mask、engine window 和 eem_window 可能分叉；仅补 abort 会改变节奏，却不会阻止下一轮继续从未更新的 Subject 选择不兼容簇。现有 effective/过渡步规则要保留，待改的是拒绝后的 Subject/eem_window 锚点归属、非连续回读的形状丢失和 clipped 是否计失败。

**量化与快速验证。** 覆盖 ELF32 default-empty/disabled、并集首拍后纯不兼容拒绝、dst_empty abort、promote 失败、narrow skip、readback None/Some(empty)/非空 clipped/非连续、升组成功后下一拍拒绝且 moved_group=true。逐轮对账 budget、planned/applied/effective/window/ledger/eem_window、Subject/moved_group、fail_streak/backoff、下一轮候选及 cgroup move；拒绝原因需有不依赖 diag_active 的计数。验证 abort 不能恢复外部 moved_group/eem_window/eem_cluster，clip 后清 streak 是否导致 0→1→0 循环。

**计划方向。** 先把“预检是否可写”“本轮是否已提交”“engine/eem_window/Subject 是否可作为下一轮锚点”定义成独立状态；保持 AArch32 可行域、两拍迁移、effective mask、回读、cgroup move 不回滚和 EEM 预算语义。不要把已实现的 effective 更新/过渡规则写成待改行为。

### P1：scenemode 的 prime 成员与两处 fold 意图

**问题。** src/chiri/mod.rs:4442-4448 的进入门槛与 :4498-4505 的饱和退出都只 chain little→big；common::chiri_core_ranges 返回 little/big/prime 三段 (src/common.rs:277-305)。sm8750 topology 在 module/config/sm8750/soc.yaml:22-24 为 little 0..0、big 0..6、prime 6..8；当前两个 fold 都漏掉 prime 对应索引。core_ctl.rs:980-985 chain 三段是代码对照，但不能单独证明两个 fold 的产品意图相同；:4475/:4496 均说明这些核不会被 offlined，旧“不同意图”说法缺证据。

**结果边界。** 纳入 prime 会改变息屏 scenemode 的进入/保持/退出决策，属于正常运行策略变化，不满足本计划的结果一致性门槛，故当前不实施。只记录两处 fold 当前 little→big 的行为并补基线断言；入口、退出 canonical set 不作修改。若未来要改变集合，须先由用户明确改变本计划的主路径结果约束。

**验证与边界。** 覆盖 sm8750 prime 索引、msm8998/其它 fallback、缺 topology、last_core_utils 空/短/离线/hotplug、阈值 0.75 边界、60s precheck、FAS/special mode、long_off=4×delay、delay=60/3000、10s 退出、300s cooldown 及多轮进入/退出。验收是候选实现与当前 little+big 基线的 scenemode 决策/计时轨迹完全一致；只允许对已明确的超时/无效拓扑 fallback 单独列出预期差异。不得把 prime 补入或集合缓存导致的决策差异当作通过。不得改 SoC 配置/阈值。拓扑 OnceLock 初始化须排除于稳态成本测试。

### P1：EEM allowed 与 cluster_pool 的核级交集

**问题。** placement.rs:298-306 的 cluster_pool 按拓扑区间构造候选；:207-211、:256-269 的窗口规划仍在整簇池上选窗，decide 接口没有 per-core allowed。affinity.rs:2550-2556 是簇级 any 门控，故规划域可包含禁止核；但不能声称 syscall 前未交集。

**真实分叉。** affinity.rs:2698-2701 已在 syscall 前把动作意图与 allowed 相交，:2702-2724 对 dst_empty 处理；因此缺口是 planner/cost/ledger/anchor 与实际写入回执不一致，而非“完全没有核级交集”。placement.rs:504-519 在写前预提交 e.left/e.cluster/window/last_move/ledger；:2726-2728 的 mask_write_allowed 拒绝直接 continue，不 abort。Ledger::commit 对 Window::cores() 摊需求，需防止被拒/裁剪窗口污染成本与回执。

**连续性和在线语义。** Window::new/cores (placement.rs:47-57) 表示连续窗口；allowed 在 affinity.rs:2487-2505 是 cpuset 读取、交集与缓存，None 在 :2550-2551 被解释为 online_all。需明确 Unknown/Empty/Cores 三态与 fail-open 契约；Some(empty) 当前不可达，不要把它写成现存分支。非连续 allowed 只能拆为连续段后分别规划，或显式拒绝。

**验证与计划方向。** 覆盖 allowed 未知/可读为空/非空连续与非连续、宽度>1、None→online_all、TTL/hotplug、mask_write_allowed 拒绝、readback None/empty/non-contiguous、两拍并集与 ledger。对于相同快照，现有 planner/commit/window 与 syscall 前 allowed 交集的有序决策和实际写入 mask 是成功路径基线；只允许修改拒绝、失败或超时后的错误归属/锚点，并逐项列出预期差异。不得新增 planner 核级过滤、改变候选/窗口/成功 mask，或改变有效 allowed 输入下的写入结果；若改动会如此，排除出本计划。cpuset cache 性能另归 P3，且必须命中/未命中结果一致。

### P1：CLG 负载统计的条件性重复扫描

**问题与作用域。** src/chiri/cpu_load_governor.rs:212-228 的 max_util 与 high_zone_hits 遍历 affected_cpus；on_load_update :565-584 另算 max 及 over/under。基线决策 tick 因而约为 2A；只有 :656-670 的 guard 成立才额外支付 A 扫描，成为 3A。A=affected_cpus.len()（spawn snapshot :1222-1224），P=其中 core_utils.get(cpu) 有值的个数；不得用 core_utils.len 或当前 online 数作分母。EEM flush/demand 遍历另列，不混入 CLG 2A/3A。

**正确口径。** 3A 由 guard `count>0 && gate>0 && old_perf>=gate && candidate>old_perf+1e-6` (:656-660) 决定；hits>=need (:670) 是扫描后的结果，不是触发扫描的条件。扫描域 A 固定为 affected_cpus；hits≤P，need=min(self.cfg.count, A)，注意 gate/hits 使用 eff_cfg 而 need 当前来自 self.cfg.count。记录该配置来源差异，不能擅自合并；默认 count=0 时 3A 不可达，具体覆盖值只作输入分层，不改机型配置。

### P2：频率迟滞归一化坐标

**问题与数学拆分。** PolicyController 的频点坐标实现为 `A(f)=(f-fmin)/max(fmax-fmin,1.0)`，见 policy_controller.rs:71-77、:133-135；policy_mgmt.rs:269-276 的迟滞路径却将旧坐标与当前 A(current_freq) 混算，实际写目标是 :267 的 `find_nearest_freq(adj)`。令 `D=max(fmax-fmin,1.0)`（沿用现有范围保护）。当 fmax>0 时，一般坐标偏差为 `C(f)-A(f)=(f*D-fmax*(f-fmin))/(fmax*D)`；仅当 fmax-fmin>=1 时才可化简为 `fmin*(fmax-f)/(fmax*D)`。fmax=0 时旧坐标未定义，单独作为边界测试。另有离散频点分量：旧分子按 `find_nearest_freq(ratio)`，写入目标按 `find_nearest_freq(adj)`；w>1 时 adj<=ratio，目标档位可能不同。两项必须分开分析，不能都塞进一个 f_ref 公式。

**方向与带宽风险。** 旧式 signed diff 相对统一坐标恒多出非负坐标偏差；离散档位也可能使 ratio 目标高于 adj 写入目标。因此统一到 A 即便 h 数值不变，也会改变有效带宽和升降频写入决策：带宽由旧坐标约 `h*fmax` 变为 `h*D`；当 fmax>0 且 fmax-fmin>=1 时缩窄比例为 `fmin/fmax`，max(1.0) 下限生效时按 `D/fmax` 比较，fmax=0 单独处理。该统一坐标改动会改变有效输入的主路径结果，当前明确排除；本计划仅接受逐输入保持旧 diff/目标/写入决策的等价计算重构。

**验证与计划方向。** 将现有公式锁定为基线：对固定快照及边界输入记录旧实现的 diff、nearest 目标、skip/write、频点和有序控制轨迹。任何等价重构必须保证所有有效输入的这些结果一致；`false_write` 或 `false_skip` 只要非零即失败。仅在候选代数式/数据路径已证明逐输入等价后才测成本，不能以有限日志样本中差异为零证明全域等价。覆盖 `diff==h`（<=门限）、h+epsilon、adj==ratio 与 adj<ratio、分子塌陷、w=0.1/1.0/2.3、负/NaN weight、fmin=0、单点及 fmax=0；空表/乱序表按真实可达性处理。不得统一坐标、改变有效带宽或要求产品接受主路径决策差异；无逐输入等价证明即排除。

### 阶段 B：先修正确性闸门

- FAS writer seam：init/apply/reset、raise/lower 半写、双写失败、write/readback 三层成功、QoS clamp、force/tamper、运行中 writer 失效和一次性 EACCES/EROFS 重开。

### 阶段 C：做可证明等价的算法优化

只推进可证明保持主路径结果的候选：CLG 扫描聚合（保持 A/P、guard、顺序）→ FAS 调用方证据传递 → EEM allocator → policy 派生量 → cpuset clone/cache。每项需证明相同输入/快照/逻辑时钟下决策、影响未来决策的状态、写入/回执与顺序轨迹等价并超过实测收益门槛。prime 集合、allowed 成功候选/窗口、迟滞坐标等会改变结果的调整不属于本计划；正确性故障修复与性能优化分批验收。

## 6. 当前结论

按当前主路径结果一致性约束，先建立基线，再处理明确隔离的失败/超时/无效输入兜底（FAS 写失败、EEM ELF32/allowed 拒绝、长帧超时），并验证故障解除后的正常轨迹回归基线；之后才推进逐输入决策与副作用轨迹等价且超过收益门槛的性能候选。scenemode 纳入 prime、EEM 成功候选/窗口变化、统一迟滞坐标及有效 gear 输入策略变化均排除。异步 telemetry 在无 lossless、非阻塞 overflow 方案前不实施。本文件和三轮只读报告不授权源码、配置、采样或行为变化。
