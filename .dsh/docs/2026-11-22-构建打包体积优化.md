## 一、打包侧（已落地）

### 1.1 XZ 算法与预设

- `xtask/src/main.rs` 的 `zip_method()` 默认 `CompressionMethod::Xz`（zip method 95），`CHIRI_ZIP_METHOD=deflate` 可退回；`zip_level()` 按算法取值：**XZ = 6、Deflate = 9**。
- **preset 6 与 9 输出体积完全相同的实测依据**：preset 决定 LZMA2 字典（6 → 8 MiB、9 → 64 MiB），包内最大成员 `core/bin/chiri` 约 6 MiB，撑不满 8 MiB 字典；而设备端解压内存随字典线性增长，故固定 6。
- **不能用 LZMA(14)**：zip 8.6.0 的 `CompressionMethod::Lzma` 写入分支直接返回 `UnsupportedArchive("LZMA isn't supported for compression")`（`zip-8.6.0/src/write.rs:2199`），只有 `Xz` 分支走 `lzma_rust2::XzOptions::with_preset(level)`（`src/write.rs:2202-2211`，level 0..=9）。
- **兼容性**：三家管理器都能解 —— Magisk 的 busybox 1.36.1 编了 `FEATURE_UNZIP_XZ`；KernelSU 的 ksud 用 `zip 8` 且开 `xz`；APatch 的 apd 用 `zip 8.6` 且开 `xz`。

### 1.2 两个打包入口共用代码

- 此前 `scripts/build-arch/build-arch.sh` 的 `pack_zip()` 用系统 Info-ZIP（Zip 3.0，无 xz 支持）打包，**xtask 的 XZ 配置对本地构建从未生效**（`ChiRiScene-#5 循星指引-569-b2659.zip` 即 Deflate 产物；`-b<分秒>` 后缀是该脚本用 `date +%M%S` 加的）。
- 现该函数改调 `cargo xtask pack`：打包 `output/` 下最新模块目录（跳过 `.` 开头的工作目录）、命名 `<目录名>-b<分秒>`、末行回吐 `zip=<路径>`，`--dir` 可指定目录；与 `cargo xtask build` 的内置打包分支共用 `zip_method()` / `zip_level()`。
- **权限位**：`xtask/src/zip_ext.rs` 用 `unix_mode()` 把每个条目磁盘上的 `st_mode & 0o777` 写进 zip 外部属性（zip crate 的 `FileOptions::normalize()` 未设权限时默认写 0644，会丢掉 `core/bin/chiri` 等 0755）。

### 1.3 只进二进制的配置（本次新增 i18n）

- `xtask` 组装 `output/.temp` 时删除：`config/feature.yaml`、`config/normal/{tuned_profiles,scenemode,fas}.yaml`、`config/rhine-init.yaml`、`config/normal/fas/`、各 SoC 目录的 `feature.yaml`/`soc.yaml`，以及 **`config/i18n/`**。
- **i18n 剔除依据**：ftl 由 `include_dir!("module/config")` 编译期嵌入（`src/common.rs:1065` 的 `CONFIG_DIR`；`embedded_ftl_str` 取 `i18n/zh.ftl`，其余语言回退 `i18n/en.ftl`），`src/i18n.rs:22` 明确「不读磁盘 i18n 目录」；`customize.sh:355` 注释亦说明是随包副本；WebUI 文案在 `webui/src/i18n/*.ts`，不读 ftl。
- **仓库源文件必须保留**：`build.rs:346` 的 `assert_required_configs()` 把 `i18n/zh.ftl`、`i18n/en.ftl` 列为必需项（缺了 panic）；`webui/scripts/fetch-fonts.mjs:96` 读 `zh.ftl` 收集 CJK 字表做字体子集化（删了会缺字）。剔除只发生在打包副本上。

### 1.4 实测与校验记录

- XZ 包：`output/ChiRiScene-#5 循星指引-570-b2839.zip` = **2,820,576 B**（117 条目，`config/i18n` 已无）。
- 解包一致性：bsdtar（libarchive 3.8.11）解出的 66 个文件与产物目录 `diff -r` 零差异、权限位 0 处不匹配；此前对含 i18n 的包亦在真机用 `/data/adb/ksu/bin/busybox unzip` 验证过 `core/bin/chiri` 的 sha256 与 `-rwxr-xr-x` 权限一致。
- 嵌入未受影响：在 `core/bin/chiri` 内可直接 grep 到 `zh.ftl` 原文（如 `scheduler-module-start-failed = 启动调度器模块失...`）。
- 设备端解压耗时：XZ 228~315 ms `vs` Deflate 80 ms（安装阶段一次性开销）。
- CI 不受影响：`cargo xtask build --no-pack`，不打包 zip。

## 二、编译侧（评估结论：已到顶）

### 2.1 已到位、无需再调

- `[profile.release]`：`strip=true`、`opt-level="z"`（即 clang `-Oz`，C 依赖经 `cc` 同样映射）、`lto="fat"`、`codegen-units=1`。
- **全模块 Full LTO 已满足**：构建命令 `cargo ndk --platform 26 -t arm64-v8a build -Z build-std -r`，`-Z build-std` 让 std/core 以 LLVM bitcode 参与 fat LTO（预编译 rlib 成员是 ELF、无 bitcode，build-std 产物成员首 4 字节 `42 43 c0 de` 即 bitcode）。
- Android 26 基线：`-march` 已是 armv8-a；仓库覆盖 28 个 SoC，不能抬指令集。

### 2.2 实测 0 收益（已定案不做）

| 实验 | 方法 | 结果 |
|---|---|---|
| 段级 GC | `-Z function-sections=yes` 整编 vs 同链对照 | 二进制 6,125,792 B 相同、`.text` 0x264ac8 相同、`.rodata` 0x1fdb68 相同，**0 B** |
| zstd 裁剪 | `default-features = false, features = ["zstdmt"]` | 同上，**0 B**；`cc` 的 `-ffunction-sections` + 链接期 `--gc-sections` 早把 legacy / zdict 训练器丢掉 |

- rustc **默认已传** `-Wl,--gc-sections`（`rustc --print link-args` 可见），段级 GC 缺的只是函数级分节，而 fat LTO 在 IR 层已完成死代码消除。
- 踩坑：`RUSTFLAGS` 会下发给 `build.rs` 的 eBPF 子构建，带 `-C link-arg=-Wl,--gc-sections` 会被 bpf-linker 以 `unexpected argument '-W'` 拒收（整模块构建失败）。
- 口径提醒：中间一度出现「GC 省 4 KB」的假象，实为官方构建嵌入的是**旧 `webui/dist`**（dist 在构建后 1 分钟才重新生成）。比对必须用同一条构建链的对照构建。

### 2.3 明确不做（各有权衡）

- **ICF（`--icf=all`）**：函数地址相等性风险（依赖地址唯一性的代码、函数指针比较），不算零影响。
- **`--no-eh-frame-hdr` / panic=abort**：前者削弱崩溃栈，后者摧毁 `catch_unwind` 自愈（`src/chiri/mod.rs:2887`、`src/monitor/mod.rs:32` 等）。
- **packed relocations（`--pack-dyn-relocs=android`）**：纯编码变化、Android 26+ 支持，可减 raw 约 0.26~0.30 MB、改善冷启动；但 `cargo-ndk` 会注入 `-Wl,-z,max-page-size=16384` 等 flag，重设 `RUSTFLAGS` 有丢注入风险，且对 zip 只值 −20~35 KB，收益/风险不划算，暂不做。
- **PGO/BOLT**：采样式 PGO 已按用户决定落地为长期任务（`src/pgo.rs` + WebUI 开关 + 离线换算链待做）；daemon 实测仅约 5.7% 单核 CPU（60 s 采样 682 samples），绝对收益上限有限。
- **字体 / mock-shell / remote_push / fluent / regex**：分别影响视觉、无 KSU 时的 WebUI 效果、远程推送功能、i18n 能力与用户正则语义，均被双零约束否决。
