- 输入 `devimpbin/SYSTEM_LAST_KMSG@…PJZ110_11.F.07…dat.gz`；panic = kernel panic（非 PMIC 硬复位），
  停在 s2idle 挂起过程，链 `qcom_wdt_bark_handler ← cpuidle_enter_s2idle+0x98 ← do_idle ← cpu_startup_entry`。
- 铁证：`vWdog-CTL: 1, vWdog-time since last pet: 206, vWdog-expired status: 1` ⇒ gh-watchdog 实际超时
  206 tick ≈ 6.39 s（≈32 Hz，即 32.768 kHz/1024），**不是申请的 20 s**（SMCCC SET_TIME 未生效/被钳位）。
- 装置侧时间线：pet 16:38:35.10 → 挂起 6.284 s（console 静音）→ s2idle 入口 → 空转 0.11 s（16234 次循环，
  sched_clock 只走 105.769 ms）→ 206 tick 到期 bark → panic ≈16:38:41.5。olc 16:40:58 取 dump。
- 教训：**suspend/resume cycles 字段时基不可靠**（折算 2.856/1.924 GHz 与 boot log 19.2 MHz 不符），
  一律用 sched_clock 差 + vWdog tick 反推；sched_clock 在 s2idle 中冻结 ⇒ printk 时间戳系统性落后墙钟。
