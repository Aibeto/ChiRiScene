# SM8550（8 Gen 2）OPP 阶梯与调度相关硬件事实

- 来源：上游主线 `arch/arm64/boot/dts/qcom/sm8550.dtsi`（torvalds/linux master，Linaro 2022），
  本地副本 `devimpbin/sm8550.dtsi.txt`（6211 行）。
- 定位：**校准基准，不是运行时输入**。ChiRi 读不到 DT；频率档位以
  `scaling_available_frequencies` 为准，capacity 以 `cpu_capacity` 为准。
- 与真机核对：OPP 频率阶梯与日志 `P0: 307-2016 / P3: 499-2803 / P7: 595-3187` 一档不差；
  capacity 对不上（见下）。

## 1. 簇拓扑与 policy 编号（已证）

| 簇 | CPU | capacity-dmips-mhz | dynamic-power-coefficient | 频域 | sysfs policy |
|---|---|---|---|---|---|
| little (A510) | cpu0-2（3 核） | 326 | 251 | cpufreq_hw 0 | **policy0** |
| big (A715) | cpu3-6（4 核） | 693 | 447 | cpufreq_hw 1 | **policy3** |
| prime (X3) | cpu7（1 核） | 1024 | 1057 | cpufreq_hw 2 | **policy7** |

policy 名 = 频域内首个 CPU 号。独立佐证：`domain-idle-states` 分配也是
cpu0-2 → little、cpu3-6 → big（4 个）、cpu7 → prime。
代码口径一致：`chiri_core_ranges()` 8550 = little 0..3 / big 3..7 / prime 7..8（src/common.rs）。
**勿再按「little 0-3 / big 4-6 / policy4」口径理解**（那是 8475 布局）。

⚠ capacity 例外：真机 FAS 日志算力 = 280 / 855 / 1024，与 mainline DT（326 / 693 / 1024）
不符 → 厂商板级 DTS 覆盖了 capacity。**算容量一律读真机 `cpu_capacity`**，
本文件的 capacity 只作 mainline 参照。

### 用法提醒（floor 对齐）

内核对 `scaling_max_freq` 写入的 clamp 是**向下取最近档**：写 1900000（little）会落到
1785600，写 1800000（big）落到 1785600。写非档位值会得到「期望 ≠ 实际」的假性
不匹配。2026-09-26 起 CLG / tuned / PowerBase 的取档已改为 **floor 对齐**
（≤ 目标的最大档）后再写：账实一致、同值不落盘的去重生效、不再比决策多给一档。
FAS 锁频（min=max）与 fast.rs 锁 hw_max 取的是表内真实档，无需对齐。

## 3. idle 深度与唤醒代价

| 状态 | 作用域 | exit-latency | min-residency | 备注 |
|---|---|---|---|---|
| silver-rail-power-collapse | little 每 CPU | 750 µs | 6700 µs | local-timer-stop |
| gold-rail-power-collapse | big 每 CPU | 1300 µs | 8136 µs | local-timer-stop |
| goldplus-rail-power-collapse | prime 每 CPU | 1350 µs | 7480 µs | local-timer-stop |
| cluster-sleep-0 | 簇级 | 2350 µs | 9144 µs | 整簇空闲才可达 |
| cluster-sleep-1 | 簇级 | 4400 µs | 10150 µs | 更深 |

推论：prime 睡实了要 ≥7.5 ms 空闲、唤醒 1.35 ms。FAS `migration_cost_ns=400000`
（400 µs）远低于唤醒 prime 的代价 → 调度器倾向把任务搬离睡着的 prime，
与「prime 空转就压/下线」同向，该值不用为唤醒代价放大。

## 4. 其他

- 每个 CPU 节点带 `#cooling-cells = <2>`：CPU 注册为 thermal cooling device，
  内核温控限频是独立于 ChiRi `thermal_cap_pct` 的第二层——「写了 max 却上不去」
  先查 OPP 对齐，再查 thermal cooling，别只怀疑外部压制。
- 全部 CPU 共享一个 L3 节点（`l3_0`），跨簇迁移不丢 L3（丢 L2）；
  `cpu-map` 在上游是平铺的 cluster0{core0..7}，调度拓扑分组实际靠
  capacity + freq-domain + idle 域表达——不要拿 `cpu-map` 当簇划分依据。
