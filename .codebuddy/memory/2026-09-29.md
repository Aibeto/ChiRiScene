## 默认 cpufreq 调速器改为按 soc.yaml 选型

- 需求：soc.yaml 新增字段填各种调速器，启动时读设备可用调速器、按从左到右优先级匹配首个可用，替换所有写死的 schedutil。
- 落地：`SocConfig.cpu_governors: Option<Vec<String>>` + `common.rs [governor]`（`select_cpu_governors` 一次算定进 OnceLock，`cpu_governor_for_policy(pid)` 取值，兜底常量 `schedutil`）；三份 soc.yaml 加 `[cpu_governors]` 段（末位放 performance 兜底：前面都不可用时才落到它）。
- 调度启动时在 `apply_system_tweaks` 内第一步算定（新 i18n key `governor-selected`），早于 `cleanup_residue`（mod.rs:1448）与 CLG/特调接管。
- 写死点已替换：CLG worker / tuned / power_base / fast / governor.rs 残留清理（原 `FALLBACK_GOVERNOR` const 删除）。
- 校验：`cargo +nightly check/clippy -p chiri --target aarch64-linux-android` 通过，改动文件无新告警。
- 未做：真机验证（新 key 日志是否按预期选到 schedutil）。
- 审查后修：选型表改 `OnceLock<Mutex<HashMap>>` 并支持惰性补算——原「启动一次算定」跑在 `force_online_all` 之前，启动期离线的簇进不了表、之后恒落兜底 schedutil；停摆期 `apply_system_tweaks` 被跳过、退出停摆时重建块又早于补算，同样落兜底。现在 `cpu_governor_for_policy` 缺谁补谁（返回 String，写入点不变）。
