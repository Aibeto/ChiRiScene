## logd_1005-021253 分析（A01-06 / 30106 / 8550 PHB110 A16）

解压目录 `devimpbin/1005-021253/`，单版本单机型，24.7h / 5 段 daemon / 放电 46.9 Wh。

主结论三条（详见当日对话产出，未落盘为独立文档）：

1. **屏幕状态抖动是这台机的头号问题**：24.7h 内息屏 355 次 / 亮屏 354 次成对翻转，息屏持续中位 14~21s，超 5 分钟的息屏全包只有 5 次。后果是
   `scene_mode_delay_secs=300` 门槛几乎不可能达成（8 次进入、7 次被饱和保护踢出），且 709 次翻转 = 709 次 CLG doze 配置重建。
   判据侧：`debug.tracing.screen_state` 在这台机出 1/2/3/4 四值，只有 ==screen_off_value(1) 算息屏，3/4 被当亮屏
   （state=3 样本均值 2.60W、state=4 1.73W，夹在息屏 0.93W 与亮屏 3.95W 之间，疑似 AOD/半亮）。
   现有去抖 2×150ms + 200ms 最小间隔拦不住秒级抖。
2. **scenemode 饱和退出没回滞**：进入/退出共用 0.75 与同一批核、单核 `max_util ≥ 0.75` 持续 10s。
   8550 于 2026-10-01 置 `scenemode_offline: false` 后仍被踢（本包实证）。
3. **中档 cap=60 压不住温度**：末批 100(34→41℃) → 85(41→43℃) → 60(43→44℃，2179s)，包尾仍在 60 档且温度上行；
   cap60 档 battT 区间 41~44℃，解除点 41.5℃ 全程没碰到。

## logd_1004-233049 分析（8650 PJX110 / A01-04 + A01-06 混装 / 20.5h / 13 批次）

解压目录 `devimpbin/1004-233049/`，放电 67.1 Wh / 均值 3.27 W。能量分布：lolm 31.78 Wh(47%)、bili 17.10(25%)、微信 5.72(8.5%)；
按 mode：fas 32.42 / default 17.66 / playback 17.05 Wh。用户当天玩了 5.9 小时 lolm。

1. **FAS 与热阶梯脱节（头号问题）**：FAS 只有电池 45℃ 单点护栏，CLG 的 41/43/45℃ 三级 cap 完全不作用于 FAS。
   lolm FAS 段电池均值 42.5℃、53.6% 的时间落在中档区间，但只有 4.6% 触发 45℃ 护栏 → 热保护在 FAS 里基本空转。
   附带澄清：FAS 段 snap 的 `cur/max=100%` 是 min=max 双写的构造结果，**不是锁 hw_max**（实际只有 hw_max 的 ~55%：little 1498 / big 1930 / prime 1979 MHz）。
2. **120fps 档过供**：fps 分桶 `>=125` 占 33.9%（p50 123 / p95 128），稳态 perf ≈0.59 → 有下探空间（前置：8650 帧源不稳未修）。
3. **延迟退出期（15s）mode 仍写 fas** → 微信/launcher/TIM 被记成 fas 并吃 FAS 频率（8.1W / 7.5W / 6.4W）。
4. **governor 残留 performance**：23:12:10 已恢复 uag，23:14:40 又见残留；23:14~23:30 四次重启无 128MB 行、无 panic，23:30:49 出抓包 → 外部触发。
5. **daemon.log 提前停写 8m14s**（进程仍活，status.csv 正常写）→ 掩盖死亡现场。
6. **tick 去重修复在 A01-06 生效**（台账待复核项结案）：bili playback big 从 29~41 行/簇/秒降到 2.75~2.98。
7. 本包 status.csv 无 `cpu_dyn_w`/`resid_w`（采集早于 10-05 落地）→ dvenergy 不出表属预期。
