---
name: 计划 = 改进方案本身，只给方向不给具体修改值
description: 用户要"改进计划"时直接写方案正文并落盘 plan.md；不写流程式计划、不指定目标数值
type: feedback
---

**规则**：三件事必须同时满足。

1. **计划正文就是改进方案本身**：现状事实 + 建议方向（改哪个旋钮、往哪边改、依据、回退），不是"怎么写分析/怎么验证"的流程计划。
2. **不给具体修改值**：不写"字段 X 由 A 改成 B"这类定值处方。现值只作为事实列出，目标量值留给实现时（按频表 floor 对齐、按真机观察）确定。
3. **说要改计划就真改文件**：结论必须落盘到 `.codebuddy/plans/<会话id>/plan.md`，不能只在对话里陈述。

**Why:** 2026-09-28 用户连续三次纠正：先嫌计划是"分析计划"而非改进计划（"我让你分析后提出改进计划，不是让你提出分析计划"）、再嫌只在对话里说而没改 `plan.md`（"plan.md 改了吗光在这碎嘴皮子说说说，你这算计划吗你分析了几个地方你就拍板了"）、最后要求去掉具体修改值（"计划中不要给具体的修改值指导，只给建议"）。动机是把未经验证的定值当成结论 = 伪精度。

**How to apply:** 用户说"制定改进计划/策略"→ 直接产出方案，按收益×置信度排序；数值型处方改写成方向（"下调/收紧/拆除，量值待定"）并挂上能效模型或前沿依据；改完给文件级 diff 清单，不额外解释流程。评估与准备 ≠ 批准开工，本仓库仍要求"没说开始改就不动源码/配置"。
