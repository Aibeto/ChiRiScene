---
name: 长期记忆必须与代码核对后才改
description: 用户会主动指出项目记忆过期；更新记忆时先读当前代码核实，且只改用户指定的条目，不外溢
type: feedback
---

项目记忆（各环境目录下的 `memory/MEMORY.md`）会过期，用户发现后会直接指出。更新时：

1. **先读当前代码核对，再落笔**——不要凭印象改写，也不要把「过去写下的结论」当成现值；
2. **只改用户圈定的条目**，其余即使看着存疑也先列出备查、不动手；
3. 改完给**行级变更清单**（原值 → 现值），让用户能快速复核；
4. 若某条指出要改的内容其实不在该文件里（已在别的文档同步过），直接说明「无需改」并给出出处，不要为了凑数改写相邻条目。

**Why:** 记忆里混着「契约数字」（预算、门限、 interval 单位）与「判读口径」（日志帧格式），代码改动后这些是最容易失真、失实后又最难发现的部分——按过期记忆做的判断会把人带到沟里。

**How to apply:** 用户说「你的知识库太旧了 / 这里已经不是这样了」时，先确认指的是哪份记忆文件（会话记忆 vs 项目记忆），再用上述流程处理；一次只动被点名的范围。

**连带的分级要求（2026-09-25）**：问题按级别分流——只有影响行为/正确性/契约的才进待办与记忆（如判据失效、口径失真、体积失控）；**链接悬空、`.gitignore` 漏项、参数调优建议这类一律不记录、不进待办清单**，说完就完，别在后续汇报里反复挂账。
