## 3. FAS 失效根因与修复（本次代码改动）

现象：2210132C 上 status.csv 有 `mode=fas` 行（858 / 1604 行），但 fps 列全空，
daemon.log 无 `fas-gear-switch`；snap 侧 fas 段 `cur==max` 且整段恒定
（little 1785.6 / big 2258.9 / prime 2607.6 MHz，cur/max=100%，governor=performance）。

根因：`libgui.so` 里 `android::Surface::queueBuffer` 的 mangled 名随 Android 版本变化，
硬编码的短/长签名在该机型都解析失败（`PID 切换失败: error resolving symbol`），
uprobe 挂不上 → 无帧 → FAS 档位永不调整。失败后每 500ms 重试一次 attach，
每次都要解析一遍 libgui 的 ELF 符号表，并每秒刷 2 条 warn（一个会话数千行）。

改动（`src/monitor/fps_monitor.rs`）：
- 新增 `scan_queue_buffer_symbols()`：读 ELF64 dynsym，按 `_ZN7android7Surface11queueBufferE`
  前缀取全部变体名；候选顺序 短签名 → 长签名 → 扫描变体。
- attach 失败退避 + warn 降频（`report_attach_failure`）：符号类故障 60s、其余 1/2/5s；
  首次与每 10 次打 warn，其余降 debug。
- 无探针时 poll 超时改 `idle_poll_timeout()`（退避窗口内不再解析 ELF）。
- i18n（zh/en）新增 3 条：`attach-symbol-name` / `symbol-scan` / `frame-source-missing`。
- `cargo check -p chiri --target aarch64-linux-android` 通过（有 `Checking chiri`，无 warning）。
