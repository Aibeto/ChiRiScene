## WebUI「导出历史日志」未压缩完就报完成（Bug 修复）

## WebUI 导出进度条「永远 0% / 压缩段不动」（口径重做，用户选 /proc 方案）

用户追加报告：进度条也不准，从来没见它跑过，都是 0% 然后直接消失显示已导出。

- **根因两条**：① 百分比用「`tar -v` 行数 / 文件数」，而 `>> "$PROG"` 是**文件**重定向 → tar 的 stdout 块缓冲（4KB）；`logd/` 只有十来个归档包，verbose 输出总共才几百字节，**整段打包期间 `PROG` 一直是空文件** → `done=0` → 0%。② 即使不缓冲，该口径也只覆盖「打包」，而耗时大头是 gzip（logd 里是已压过的 `.tar.lz4`：gzip -6 几十 MB/s，tar 是几百 MB/s 的纯写）→ 压缩段百分比恒为 99%。上一轮修的「产物一出现就报完成」恰好把这两条都盖住了。
- **方案（用户选定）**：进度只取**文件/内核读数**，不再依赖脚本回显。打包段 = `.part` 字节 / 源总字节（pack.sh 用 `du -sk` 预算写 `total_file`，语义由「文件数」改为「字节数」）；压缩段 = `/proc/<压缩器 pid>/io` 的 `rchar`（已读入输入字节）/ `.tar` 字节——压缩器一律**后台跑**并以 `$!` 写 `<fail>.pid`（压缩结束即删）来暴露 PID，对 chiri/系统 gzip 一律成立。百分比分母 = 源总字节 + `.tar` 字节（打包期间 `.tar` 未出现，用源总字节顶替，两值接近故不回跳），封顶 99。
