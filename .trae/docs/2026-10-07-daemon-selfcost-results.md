## 2 方法与修订点（相对旧脚本）

| # | 修订 | 说明 |
|---|---|---|
| 1 | 显式清单 | 硬编码 `CASES` → 必需 `--manifest`；无参数/未知子命令直接报错，不回落 feas |
| 2 | 按字段名取值 | `csv.DictReader`；必需列缺失即失败，坏时间/坏 CPU 逐项计数丢弃，空值计数保留 |
| 3 | 时间轴 | 按文件顺序展开跨午夜；回退不能判定为午夜（非 18h→6h）记 `ambiguous` 并切断连续段 |
| 4 | 屏幕主层 | 改用 `screen_prop`（`debug.tracing.screen_state` 原始值）分层；旧脚本的 `q[5]`（=`screen_on`）不再沿用；`screen_on` 只作辅助并单列冲突 |
| 5 | 差分前提 | 只在同文件、同段、双端 `type/mode/package/screen_prop/clg_active` 一致且 CPU 非递减内差分；任一变即切段 |
| 6 | 分层 | strict(dt=1s) 与 short(0<dt<10s) 两层独立报告；均值 = `sum(delta)/sum(dt)` |
| 7 | 去掉无依据过滤 | 移除旧版 `0<=delta<=3000`；未提供 `logical_cpus` 时不做物理上界截断，只报异常最大值 |
| 8 | 分母 | 覆盖分母改用**有效间隔时长**而非行数；未知时间不纳入均值 |
| 9 | 帧保留 | aff `@S` 保留日期/源文件/出现序号与全部重复秒内帧，不用 set/dict 覆盖 |
| 10 | 诊断证据 | diag 只承认显式开关字样为 `confirmed`；日志首尾只作 `coverage_only` 文件覆盖证据 |
| 11 | 配对收紧 | pair 三个 status 端点必须同属严格连续层；拒绝多帧/相邻帧/相位不确定窗口；不按符号断言原因 |

## 3 旧算法复现 vs 修订（并列，不迎合旧数）

### 3.1 feas

| case | 旧：缺失秒占比 | 新：覆盖（有效时长/跨度） | 旧：逐秒差分 n / 均值 | 新 strict n / 均值 | 新 short n / 均值 |
|---|---|---|---|---|---|
| P1 | 5.7% | 97.6%（8852/9068） | 8258 / 53.6 ms/s | 7691 / 53.7 ms/s | 684 / 26.9 ms/s |
| P2 | 20.9% | 78.6%（10568/13437） | 10396 / 119.0 ms/s | 9181 / 118.9 ms/s | 1117 / 97.8 ms/s |
| P3 | 52.2% | 62.4%（26598/42635） | 17684 / 44.0 ms/s | 16951 / 43.9 ms/s | 2530 / 6.9 ms/s |

- **总量口径基本一致**（旧 53.6/119.0/44.0 ↔ 新 strict 53.7/118.9/43.9），说明修订没有推翻原有总量计算。
- **缺口口径被重算**：旧「缺失秒」=（跨度−行数）/跨度，是**按行数**的粗算；新覆盖用有效间隔时长，并扣掉边界排除时长（P1/P2/P3 分别 206/284/316 s）与跨缺口时长。差异（5.7%→2.4%、20.9%→21.4%、52.2%→37.6% 未覆盖）不构成「丢行率」，缺口原因仍未知。
- 旧脚本报的 P3 52.2% / P2 20.9% / P1 5.7% 因此**不直接引用**，以本轮新口径为准。

| case | 旧切换（screen_on/pkg/mode/clg） | 新切换（screen_prop/pkg/mode/clg） |
|---|---|---|
| P1 | 70 / 47 / 8 / 7 | 73 / 37 / 3 / 2 |
| P2 | 34 / 123 / 41 / 41 | 34 / 95 / 24 / 24 |

差异来源：屏幕维度由 `screen_on` 换成 `screen_prop`；旧脚本的切换计数把「缺行」也当邻接，新口径只在**同段相邻 1s** 内计切换。

| case | 旧 ≥60s 段（按 screen_on+pkg+mode） | 新 ≥60s 段（按五字段身份） |
|---|---|---|
| P1 | 32 段 / 5648 s（62% 跨度） | 28 段 / 2518 s（28.4% 有效时长） |
| P2 | 40 段 / 7662 s（57% 跨度） | 13 段 / 1434 s（13.6% 有效时长） |
| P3 | 72 段 / 14124 s（33% 跨度） | 81 段 / 10495 s（39.5% 有效时长） |

- 同身份连续区间中位段长为 6 / 6 / 3 s，最长 155 / 321 / 309 s → **稳定区间很碎**，与计划 §12.1 的预判一致。旧「≥60s 覆盖」偏高，是因为只按三字段分层且分母用跨度；新口径把 `screen_prop`、`clg_active`、`type` 也纳入身份，P1/P2 掉到 28.4%/13.6%。
- 分母为 0（无可比样本）时覆盖报 `insufficient` 而非 0%（`fmt_pct`），如单行文件的覆盖。

### 3.2 diag

| case | 旧：main 覆盖秒 / on 样本 / off 样本 | 新：文件覆盖秒 / confirmed_on / confirmed_off / coverage_only / unknown |
|---|---|---|
| P1 | 9070 / 8258（53.6）/ 0 | 8818 / 0 / 0 / 7690（53.7）/ 1 |
| P2 | 13439 / 10396（119.0）/ 0 | 10804 / 0 / 0 / 9181（118.9）/ 0 |
| P3 | 42637 / 17684（44.0）/ 0 | 23683 / 0 / 0 / 16951（43.9）/ 0 |

- 全仓无 `dev_record` 开关的显式日志行（显式证据命中 0 行），因此 **`confirmed_off` 样本恒为 0**。
- 旧脚本把「main 日志覆盖秒」直接当成「采集开」，这是把**文件覆盖证据**误当**开关证据**；新口径区分为 `coverage_only`，并不填满中间秒。
- **结论**：现有日志里没有「诊断关闭」的对照窗口，「剩余量是否非诊断」用现有数据**无法判定**，与计划 §12.1(2) 一致；要判定必须新增对照采集。

## 4 候选与观察（不作机型归因）

- 分层维度齐备：`screen_prop` / `mode` / `package` / `clg_active` 均有可比样本，strict 层按同身份分层给了 top-8。
- 屏幕主层两档样本量大且自耗有量级差（示例 P3：`screen_prop=1` 的 `launcher` 18.5 ms/s vs `screen_prop=2` 的 `deepseek.chat` 44.0 ms/s），**只能排候选**，不能当机型归因。
- `playback`/`clg=0` 组合自耗偏高（P2 `tv.danmaku.bili` 208.6 ms/s，P1 74.9 ms/s），与旧脚本「播放态」证据方向一致；落行次数≠执行次数，相关不等于执行次数。
- 异常最大值（未截断，未提供 `logical_cpus`）：P1 170 ms、P2 400 ms、P3 180 ms，均留待 A2「异常单列」复核。
- aff 帧均 `ntop/nfg` 有量级（P1 平均 nfg 220.8，P2 196.1，P3 164.9），说明线程规模常态几百，与计划 §1.2 一致。

## 5 限制与不可分部分

1. **亮屏 @S 无法分离**：亮屏 98%+ 帧距为 1s，跳帧对照样本既有偏又反向，乏可信数字。
2. **诊断关闭对照缺失**：无 `confirmed_off` 样本，剩余量的「是否非诊断」不可判定。
3. **`/proc/self/stat` 是整进程 CPU**：含 monitor/诊断/调度线程，不含 eBPF 系统事件路径成本。
4. **跨场景减法**：息屏估的单帧成本去扣亮屏总量属跨场景减法，本报告**不给** P1≈26/P3≈29/P2≈86 的剩余量重算。
5. **身份缺口**：config 全为 unknown，禁止跨 unknown 比较，故不作跨 case 归并。
6. **缺口原因未知**：缺口数/最大值已计入，但不外推、不补零。
