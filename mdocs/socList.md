# 已适配 soc 和适配程度列表

表格列口径：

- `适配情况`：**已适配** = 有真机验证与调优结论；**测试中** = 有真机数据但调优未收口；**配置就绪** = 由 `freqbench_tensor/results/` 实测折算批量生成配置（含帕累托前沿表），**未做真机调优**，参数继承根 `feature.yaml` 默认。
- `帕累托前沿`：该机型 `soc.yaml` 内是否已落 `frontier_policy` 受控生成块（`- [x]` = 有逐档能效模型与实测 capacity，运行期可查表）。
- `默认启用`：出厂即接管 CPU 调度（片段在 `src/common.rs::CHIRI_SOC_HINTS` 内）。批量行除 `msm8998` 外均为 `- [ ]` -- 配置已就绪但未进 hint 名单，未经真机验证不默认接管。
- 排列顺序：**按厂商归类**（高通骁龙 / 三星 Exynos / 联发科 MediaTek / 谷歌 Tensor）；骁龙再分 `4xx / 6xx / 7xx / 8xx` 子类，同类内**型号数字从小到大**，8xx 的新命名世代（`8+ Gen 1` 起）接在 `888` 之后。
- 批量行的功耗/算力来源 = `freqbench_tensor/results/<soc>/`，折算 `devimpbin/batch_ingest.py`，配置生成 `devimpbin/gen_soc_config.py`，能效模型文档 `mdocs/<soc>/<soc>-freq-power.md`。

## 未纳入的机型

`freqbench_tensor/results/` 里有数据但**功耗列不可用**，折算不出可信的逐档能效，故不生成配置：

- `t8103`（Apple M1）：燃料计读数恒为 0（`housekeeping.power_mean == 0.0`），逐档功耗全零，量不了动态功耗。
- `mt6768`（Helio G70）：满频簇功耗仅 2.6 mW / 0.5 mW 量级，原始读数被单位缩放过。
