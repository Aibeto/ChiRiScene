# SM8650 频率 ↔ 功耗对照（8 Gen 3 实测能效曲线 + common 内核 OPP）

> 索引：`[source]` `[caliber]` `[efi]` `[limits]`

- **本文件是溯源记录，不是生成器输入**：`scripts/frontier_policy.py` 需要「逐档**实测**簇功耗 +
  簇算力」并按 n 核做漏电校正，本机**没有**该数据（`freqbench_tensor/results/` 无 sm8650）。
  实际落表走 `scripts/curve_anchor.py --soc sm8650`（锚点 `devimpbin/web/anchors_sm8650.yaml`，
  gitignored、可重生成）。**重跑别用 frontier_policy.py**——本文件刻意不产出簇级算力表，
  避免被误当实测输入。
- 频率档位来源：`common` 内核（android-mainline）`arch/arm64/boot/dts/qcom/sm8650.dtsi` 的
  `cpu{0,2,5,7}_opp_table` 静态 OPP 表，与厂商件 `AYNTechnologies/linux/.../sm8650.dtsi` 逐档相同。
- 功耗来源：8 Gen 3 实测能效曲线「能效曲线-架构工艺-FP」（AndSPECmod + 假电池整轨实测、多项式拟合，
  V1.0.7，2026.08.09，作者 Timysy_小添），按核心取 A520/A720/X4 三条曲线。

## 2. [caliber] 折算口径（三步，缺一不可）

1. **横轴是整机功耗差**（假电池整轨实测，含板卡/漏电成分），不是单簇纯动态项 → 绝对瓦数偏高。
2. **纵轴是 SPEC2006 FP 单核分**，须反解成频率轴才能喂相对模型：`score = score_max × (f/f_max)^α`，
   α = 0.7（IPC 随频率衰减的经验指数）。原因：`sweet_index` 的 `cap_rel` 是**硬编码 `f/f_max`**
   （`src/chiri/energy_model.rs:262`），没有「用分数当算力」的入口。α 取 1.0 vs 0.4 会改变甜点档位，
   但频率位置稳定落在 60–75% 区间。
3. **`dpc` 绝对值不参与决策**：`build()` 的归一化（扣首档 ÷ 跨度）把它**完全抵消**，
   `dpc=100` 与 `dpc=588` 得逐位相同形状 → 故本文件不提供 `voltage_mv`、不反解 Cx。
   **代际进步只能由 V(f) 曲率承载**，这也是逐档电压缺失仍属唯一未闭合口径的原因。

## 4. [limits] 边界与注意

- **读图误差**：曲线为逐点约读（每簇 6–10 个可辨点），甜点实测可漂 **±2 档**，按**体质误差**接受
  （用户 2026-10-23 定）。不做读数微调——调了也是在同一误差带内挪。
- **绝对量级不可信**：横轴含整机底噪，`power_w` 的绝对值高于真实单簇动态功耗；相对模型的机内决策
  只看形状（正确即可），但**跨簇比较依赖簇间相对比例**，故 prime/big 比值若失真会改变跨簇落点。
- **甜点结果**（`build()` 归一化 + `sweet_index`，回归 `src/common.rs::frontier_config_tests::sm8650_frontier_usable` 守卫）：

  | 簇 | 甜点档 | 甜点 kHz | 占本簇峰值 |
  | --- | ---: | ---: | ---: |
  | little | 19 / 25 | 1843200 | 81.4% |
  | big | 32 / 47 | 2323200 | 73.8% |
  | prime | 31 / 49 | 2246400 | 68.0% |

- **EEM 落点必须等于真机档位**：EEM 返回的 kHz **不经 `find_floor_freq` 对齐**就直接写
  `scaling_max_freq`（`src/chiri/cpu_load_governor.rs:715-728`），故本文件频率必须与
  `soc.yaml [freq_khz]` 逐档一致——已核对一致。
- **未闭合**：逐档电压。DT `opp-microvolt` 计数 = 0；电压只在 EPSS 运行期寄存器
  （`common/drivers/cpufreq/qcom-cpufreq-hw.c`：`reg_volt_lut = 0x200`、`LUT_VOLT = GENMASK(11,0)`、×1000）。
  取证后可反解真实 V(f) 并用 `curve_anchor.py --check` 对账替换。
