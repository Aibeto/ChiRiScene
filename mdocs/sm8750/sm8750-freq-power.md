# SM8750 频率 ↔ 功耗对照（参考曲线折算，无实测表）

> 索引：`[source]` `[caliber]` `[efi]` `[limits]`

- **本文件是溯源记录**：本机无 `freqbench_tensor/results/sm8750/`，无逐档实测簇功耗，
  故 `scripts/frontier_policy.py` 走不通；`frontier_policy` 受控块由 `scripts/curve_anchor.py` 生成。
- **两簇布局，没有小核簇**：6× Oryon performance（CPU0-5）+ 2× Oryon prime（CPU6-7），
  八核同为 64 位 Oryon。`topology.little` 是空区间、`frontier_policy.per_cluster` 无 `little` 键——
  **这是合法配置**，不是缺失（回归 `frontier_config_tests::sm8750_frontier_usable` 已按两簇断言）。
- `[idle]` / `[dpc]` 两段在 `soc.yaml` **刻意留空**：mainline 与厂商 dtsi 均不给 sm8750 的 CPU OPP，
  没有可信的 `dynamic-power-coefficient` 可用 → **不编造值**。
- **本文件 §3 只给 big/prime**（无 little）。下表数值直接抄自 `soc.yaml` 受控块，是唯一事实来源。

频率档位与 `soc.yaml [freq_khz]` 段**逐档一致**（已核）。EEM 返回的 kHz 直接写
`scaling_max_freq`、不经 `find_floor_freq` 对齐（`src/chiri/cpu_load_governor.rs:715-728`），
故两处频率必须相同——改频表要同步改受控块。

## 2. [caliber] 折算口径

1. **来源是第三方图表折算，非本机实测**：绝对量级未经真机核对（如 prime 顶档单核 6.196 W）。
2. **相对向量使机内决策不受影响**（形状正确即可），但**跨簇比较依赖簇间相对比例**——
   prime/big 比值若失真会改变跨簇落点。待有条件时用 PMIC 实测复核（`devimpbin/batch_ingest.py` 链路已就绪）。
3. **无 `voltage_mv`**：不给电压就不反解 Cx，`curve_anchor.py` 只留功耗表（脚本对电压缺失是合法分支）。
4. `power_w` = 簇级（= 单核 × 簇核数），`single_core_power_w` = 单核口径。
   运行期 `energy_model` **只消费 `single_core_power_w`**；`power_w` 仅溯源与遥测。

## 4. [limits] 边界与注意

- **绝对量级存疑**（见 §2），只有形状可信。跨簇落点依赖 prime/big 相对比例，未实测前不做跨簇结论。
- **甜点由曲线形状决定**（`sweet_index`，回归 `sweet_point_is_scale_invariant` 证其与量纲缩放无关）：
  现配置下 big 甜点 1785600 kHz、prime 甜点 1958400 kHz。真机若发现单线程性能不足，
  **先看 `eem_press_streak` 抗饥饿释放的触发率**（触发 = 封顶确实压住了），再考虑引入 `sweet_bias` 档偏移，
  **不要直接改判据**（`agentsdocs/07-todos.md` 同口径）。
- **`[dpc]` 为空是设计**：内核 EM 公式 `uW = dpc × mV² × MHz / 10⁶`（`common/drivers/opp/of.c:1504-1507`）
  需要 dpc；本机拿不到可信 dpc 就不填，避免假值污染校准基准。
- 本文件 `§3` 数值直接复制自 `soc.yaml` 受控块；**改受控块后本文件必须同步重生成**，
  否则两处会漂移（`curve_anchor.py --check` 只校验受控块自身，不校验本文件）。
